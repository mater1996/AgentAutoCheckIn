# 数据模型

平台化 = 三张表 + 一个引擎 + 一条账本。所有表都是纯文本，可 git 版本管理。

---

## 1. 账号表 `accounts/accounts.yaml`

```yaml
accounts:
  - id: jd_main                 # 全局唯一，账本用它做主键
    app: jingdong               # 对应 activities/ 里的 app 键
    package: com.jingdong.app.mall
    user_id: 0                  # 0=主空间，999=应用双开
    login: cookie               # cookie | sms | manual
    enabled: true
    note: 主账号

  - id: mt_dual                 # 双开出来的第二个美团账号
    app: meituan
    package: com.sankuai.meituan
    user_id: 999                # 双开实例，包名不变，靠 user_id 区分
    login: sms
    enabled: true
    note: 小号
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 全局唯一账号 ID，账本主键。建议 `<app>_<别名>` |
| `app` | ✅ | App 的逻辑名，对应 `activities/` 文件名 |
| `package` | ✅ | Android 包名（主空间与双开**相同**） |
| `user_id` | ✅ | `0` 主空间 / `999` 应用双开。**双开实例的唯一区分依据** |
| `login` | ✅ | `cookie` 有持久登录 / `sms` 需短信码 / `manual` 每次人工 |
| `enabled` | ✅ | 是否参与每日调度 |

### 双开实例怎么启动

u2 的 `d.app_start(pkg)` 只起**当前用户**，对双开实例无效。必须用 adb：

```bash
adb shell am start --user 999 -n com.sankuai.meituan/<Activity>
```

实测：这样启动后前台是 `u999`，`am get-current-user` 仍为 0，
u2 的 `dump_hierarchy` / `click` 都能正常操作（见 `research/实测记录.md` 第 6 节）。

取 Activity 名：
```bash
adb shell cmd package resolve-activity --brief <pkg> | tail -1
```

## 2. 活动表 `activities/<app>.yaml`

一个 App 可有多条活动（签到、任务、领券…），每条独立启停。

```yaml
app: jingdong
account: jd_main
activities:
  - id: jd_signin
    name: 京豆每日签到
    entry: [我的, 京豆]              # 语义路径，不是坐标
    verify_any: [已签到, 已领取, 今日已签]
    window: "08:00-12:00"            # 允许执行时段
    reward:
      unit: 京豆
      amount: 7
      cny_per_unit: 0.01             # 100 京豆 = 1 元
    enabled: true
    state: active                    # active | dead | pending
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 活动唯一 ID（在同一 App 内唯一即可） |
| `name` | ✅ | 中文名，推送消息里显示 |
| `entry` | ✅ | 语义入口路径，配方生成时参考 |
| `verify_any` | ✅ | 成功判定词，任意命中即算成功 |
| `window` | ✅ | `HH:MM-HH:MM`，超出不跑 |
| `reward.unit` | ✅ | 奖励单位（京豆/金币/积分/元） |
| `reward.amount` | ✅ | 单次约得数量 |
| `reward.cny_per_unit` | ✅ | **折算汇率**，积分→人民币唯一入口 |
| `enabled` | ✅ | 是否调度 |
| `state` | ✅ | `active` 正常 / `dead` 活动已结束 / `pending` 待验证 |

### 关于 `cny_per_unit`

**折算只在这里定义一处。** 账本只记原始单位和数量，汇总时才算人民币。
兑换比例变了（比如 100 京豆从 1 元变 0.8 元）只改这一行，**历史记录不用重算**。

常见汇率参考（自用时按实际兑换页确认）：

| 单位 | 典型汇率 |
|---|---|
| 京豆 | 100 京豆 = ¥1 |
| 淘金币 | 100 金币 = ¥1 |
| 支付宝积分 | 视兑换项，约 200 分 = ¥1 |
| 美团神券 | 按券面额 |

## 3. 配方 `recipes/<account>_<activity>.json`

引擎自动生成与写回，**人不用手写**。语义步骤，坐标用归一化比例。

```json
{
  "account": "jd_main",
  "activity": "jd_signin",
  "updated": "2026-10-29T23:00:00",
  "source": "agent",          // agent | human | seed
  "steps": [
    {"do": "tap", "text": "我的", "after": 1.5},
    {"do": "tap", "text": "京豆", "after": 2.0},
    {"do": "tap", "text": "签到", "after": 2.0},
    {"do": "verify", "any": ["已签到", "签到成功", "已领取"]}
  ]
}
```

### 支持的 step 类型

| `do` | 参数 | 说明 |
|---|---|---|
| `tap` | `text` / `x,y`(归一化) / `exact` / `timeout` / `after` | 点击文本或坐标 |
| `long_press` | `text` 或 `x,y`，`duration` | 长按（默认 1.0s） |
| `swipe` | `from`/`to`（归一化 `[x,y]`），`duration` | 滑动 |
| `drag` | `from`/`to`，`duration` | 拖拽 |
| `watch_video` | `max_sec`，`skip_after` | 等待视频 + 轮询跳过 |
| `input` | `text` | 输入文本 |
| `back` | — | 返回键 |
| `wait` | `sec` | 等待 |
| `verify` | `any`（词列表）/ `fingerprint_change` | 成功判定 |

### 归一化坐标

`x,y` 都是 0~1 的比例，不是像素。换分辨率、换机型配方仍然有效。

```json
{"do": "tap", "x": 0.5, "y": 0.62}   // 屏幕正中偏下
```

## 4. 账本 `ledger/YYYY-MM-DD.jsonl`

每天一个文件，追加写，永不覆盖。一行一次执行。

```json
{"ts":"2026-10-29T09:12:03","account":"jd_main","activity":"jd_signin","status":"OK","reward":{"unit":"京豆","amount":7},"cny":0.07,"ms":1834,"evidence":"evidence/2026-10-29-jd_main-jd_signin.png","via":"recipe"}
{"ts":"2026-10-29T09:15:40","account":"tb_main","activity":"tb_signin","status":"NO_EFFECT","reward":null,"cny":0,"ms":2210,"evidence":"evidence/...png","via":"recipe","note":"点击后界面未变化"}
```

### `status` 取值

| 值 | 含义 | 是否计入收益 |
|---|---|---|
| `OK` | 签到成功，已用验证词确认 | ✅ |
| `ALREADY` | 今日已签（无需重复） | ❌（已记过一次） |
| `NO_EFFECT` | 点了但界面没变化 | ❌ |
| `NOT_FOUND` | 找不到入口 | ❌ |
| `NEEDS_LOGIN` | 掉登录 / 被挤下线 | ❌ |
| `NEEDS_AGENT` | L1 失败，已升级 L2 | ❌ |
| `LAUNCH_FAILED` | App 没起来 | ❌ |
| `DEAD` | 活动已结束 | ❌ |

### `via` 取值

`recipe`（L1 配方回放）/ `agent`（L2 现场决策）/ `human`（人工补跑）

## 5. 汇总口径

**日汇总**（当天所有账本行）：

```
今日收益 = Σ (cny where status == "OK")
今日成功 = count(status == "OK")
今日失败 = count(status in [NO_EFFECT, NOT_FOUND, LAUNCH_FAILED])
需处理  = count(status in [NEEDS_LOGIN, NEEDS_AGENT])
```

**月汇总**：按月累加，按 `account` 和 `activity` 分组。

**注意**：`cny` 在写入时按当时的 `cny_per_unit` 算好存下。汇率变化**不影响历史**，只影响新记录。这是刻意的 —— 历史收益应当反映当时的真实兑换比例。

## 6. 目录约定

```
accounts/accounts.yaml          账号表（手写）
activities/<app>.yaml           活动表（手写 + 引擎更新 state）
recipes/<account>_<act>.json    配方（引擎写回，人可读可改）
ledger/YYYY-MM-DD.jsonl         账本（引擎追加）
evidence/YYYY-MM-DD-<tag>.png   截图留证（失败项必留）
```
