# 任务组件与 focused 面板独立审计实现

本轮只修改 `runner/staged/script-validation.ts`、新增 `tests/staged-current-components-audit.test.ts` 与本文。未改 runtime/config/main、其他测试或历史 evidence/data 原件；未执行 ADB、真实 OCR、真实模型、数据库或 cron。父负责正常入口配置生成、实现归档及额外整链验证。

## 可复用接口

```ts
verifyAuditFocusedPanel({
  root, frame, config, stageId, task,
}); // 同步 panel | null

await verifyAuditTaskComponent({
  root, frame, config, stageId, task, selectedContract?,
}); // {inspection, selectedContract?} | null
```

`root` 是容纳保存帧及 sidecar 的真实目录；所有输入文件必须在其内。frame 必须与相邻保存 JSON 一致，owner 与 config.package/config.scope.userId 一致。接口均只读保存证据，不调用模型/OCR、不产生设备动作或账本权限。

focused 要求 `panelReadPolicy:'focused-v1'`、`aiPanelReader:true`。open_task 可消费完整表复用或 purpose=selected-row；后者必须精确绑定 name/instruction/done/total。return_list 必须 purpose=return-status；settle 必须 purpose=settlement。loadAiPanel 每次重核 PNG/manifest/rawResponse 哈希、owner/frame/时间、schema 与 expectedMode。collect_list/select_task 不接受 partial status。合法缺行返回 tasks=[]、inventoryComplete=false，不填造已选行，也不能作为完整盘点。返回与结算仍需上层验证实际完成。

任务接口按 `taskObservationPolicy` 选择当前或旧检查器。当前策略调用 inspectCurrentDwellBrowse、inspectCurrentLearnedBrowse、inspectCurrentImmersiveBrowse，核对真实保存 PNG/OCR。dwell 合同按完整 name+instruction 选择，沿用合同版本；learned/immersive 返回各自 current-components inspection version。

自动连续合同只能在 open_task 第一次选择；调用方必须把首次返回的 selectedContract 原对象传给后续目的地/新帧/完成帧验证。不能序列化再造对象，也不能在 task_receipt 重选；continuous-contract 内 WeakMap 同时绑定 owner 与 policy，不允许换 policy。独立接口本身不证明实际 entry、attempt 或收益；完整审计另行绑定这些证据。

## 已接入完整审计

现有 auditStableScripts/inspectAttempt 已实际调用上述两个接口，并非孤立导出：

- 完整盘点/选择、入口真实 tap 绑定、返回面板与结算均调用 focused 验证；当前策略还检查所有 observed/before_dispatch_revalidated 原始帧的 owner 与保存对象。
- 当前目的地记录必须与复算 inspection 的 state/version/reward 及当前 attempt 相符。自动连续段只选择一次合同，随后所有检查复用同一原对象。
- beforeDispatch 消费真实 engine 保存的新 frame/proposal。当前策略使用 revalidateBrowseSwipe 第五参数 `{policy:'current-components-v1',selectedContract}`，从 fresh frame 再生成坐标并比较实际派发动作；保留已选预算与单段检查。legacy 继续旧 revalidateLearnedBrowse。
- 当前完成引文由当前组件检查器直接复算，不再落回旧固定坐标 receiptVisible。receipt 的新 inspection version、完整引文、金额、path/frame、sourceRunId、attempt 与唯一 learned_receipt runtime 事件逐项一致。
- focused 结算保留正的实际余额增量、所属面板、同 attempt 回执、可见 quota 不矛盾要求；末两次样本必须 ID/路径不同、capture 时间递增且在回执后。剩余 quota 仍要求真实匹配行，缺行不提供额外完成依据。
- implementationConfig 指纹纳入 taskObservationPolicy、panelReadPolicy、aiTaskRecovery、aiPanelReader；required sources 含 ai-panel-reader.ts、browse-revalidation.ts、script-validation.ts 及实际开启的 learned/dwell/immersive 源码，旧来源合同与归档绑定检查仍执行。

原 `whole-session-zero-model` 报告 policy、非零 usage/agent/manual 拒绝、两次独立正常 session 标准均未改变。新策略不把真实 AI-assisted 会话重新归类为旧零模型成功；离线 fake model 不代表真实 AI 费用或运行记录。

## immersive 明确边界

runtime 的 ocrQuality derivation 与 reward transition 仍走独立 legacy 检查器。审计保留 verifyAuditImmersiveOcrQuality 与原 legacy transition 验证，未用普通 current inspector 替换这两条。

`current-components-v1` 与匹配 immersive 配置的 `ocrQuality:true` 或非空 rewardTransitions 组合保守拒绝，完整审计明确返回 `current_policy_unsupported`；没有修改/关闭这些配置，也不宣称分支迁移完成。普通 current immersive 只接受允许金额的当前组件，并要求完成金额等于已钉住目的地金额，不能凭 allowedRewardCoins 变化授权 20→35。旧 policy 的 quality/transition 仍按旧合同验证。未证明的 completed50 继续 unknown。
