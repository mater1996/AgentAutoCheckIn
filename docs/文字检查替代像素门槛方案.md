# 文字检查替代像素门槛方案

用户已在会话确认：正常页面用文字与位置检查；余额限定区域OCR；有歧义再交给读图Agent。最新指令“那你继续吧 有问题抛给我”授权实施与范围内复验，不启用调度，不扩大任务类型。

## 之前／现在

之前：任务面板整条header与历史PNG逐tile比对；余额必须命中历史数字精确字形，才调用OCR。动态背景和正常字形栅格变化反复阻断业务。

现在：面板身份由指定package/user、有效新鲜帧、唯一标题及位置、奖励/进度文字与任务行的布局共同确认；去掉面板身份的历史像素比对。余额由同帧限定数字区域的本地OCR提供，严格唯一整数、排除箭头/邻近金额，保留原PNG/crop/raw及hash和frame绑定，独立审计重放证据。无需逐字形库或旧背景相同。两次新鲜余额样本一致及同attempt回执、正增量仍为记账条件。两次OCR不是独立真实性证明，文字无法确定图标遮挡或静默覆盖时仍有局限。

先限定改动为任务面板身份与余额读取；首页/活动页以及任务落地页已有规则不在本次一次性替换。遇到其他像素门槛阻塞，先报告具体问题，不继续自动补图。

## 验证与执行

1. 用run216原证据先复现拒绝，实施最小文字检查与余额OCR方案。保留错误账号、缺失/重复标题、错误布局、登录/验证、非法金额和证据篡改负例。新政策不再承诺拒绝仅像素变化而OCR保持不变的合成图。
2. 历史不同余额/不同列表页离线验证；真实engine/runtime/device事件接线和独立审计一致；历史失败不回写成功，原文件不修改。
3. 必要回归和类型检查通过，独立SQLite前备份并quick_check通过后正常入口真机复验，完整采集当前任务并按批准范围动态选任务。保持设备独占、一次动作及同轮核验/记账/源码归档/息屏。
4. 需要扩大范围、改变方案、无法判明真实要求，或同一方向反复修复仍无业务进展时向用户抛出具体问题。不会为了继续运行而追加像素模板、伪造到账或启用cron。

实施和实测状态单独记录；本文不代表已经实现或验通。
