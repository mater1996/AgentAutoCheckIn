# 整轮任务编排

用户已在本群对“完整采集→动态计划→按列表顺序逐项执行→核账→返回列表继续→无候选时返回桌面并息屏”的方案回复“执行吧”。本文件记录该已批准范围，不再要求重复确认。

## 之前与现在

之前单会话执行一个任务后归档、息屏，由对话外层重新启动下一项；采集停在底部时选择未先返回顶部。

现在新增正常入口的整轮模式：保持同一个设备锁和唤醒期，每次从最新完整清单生成业务计划，回顶部选择第一项，复用单任务执行及SQLite核账归档；任务结束刷新清单和计划，直到没有允许执行的剩余项。整轮收尾按HOME返回系统桌面、读回前台、恢复stay-on并息屏读回。

## 规划与状态

- 业务计划包含逐字任务身份、做/跳过/待判、理由、剩余次数、动作方式、完成证据与停止条件。模型读取完整清单、规则和已学路由，不按标题关键词猜业务类别。
- 邀请、消费、实际游戏以及消消乐/养小羊继续跳过；跨应用、安装、相机上传、授权、登录验证仍不在执行范围。
- 保留已消耗的本批attempt，失败/未知不重试。此次实施不自动建立重试批次。之前仅为某次验收范围而skip的任务可重新按真实说明评估；明确userSkip不解除。
- 派发前持久化reservation；崩溃、未知input不重放。预派发阻挡单列待处理，避免相同证据无休止空转。
- 缺回执或收益归属不清保持unknown；仅在输入已知、确认回到所属列表时继续其他任务。实际登录/验证、输入结果不明、保存失败立即停止业务操作。
- 不增加任意业务时长、任务数、模型次数等限制。语义停止条件为无可执行项、未发生可解释进展、业务安全门槛或持久化失败。

## 验收

实现与实测分开：先离线验证多任务循环、列表变化、从顶选择、跳过延续、防重和异常停止，再用正常入口进行真机验收。空候选只能证明入口/计划/收尾，不算多任务完成率。每次真机前独立SQLite backup并quick_check，结束回读账本和息屏状态，不开启定时任务。

实施、离线结果和真机结果另存记录；本文件不声称已完成。
