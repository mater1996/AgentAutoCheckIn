# Portal读取失败后有限重试：实测

用户提出失败后多试几次。本轮限定保持同一任务列表、5次state_full?filter=false、每次返回后等待2秒，不导航/滚动/任务点击，不重新绑定Portal无障碍。正式临时session在不存在监听时启动HTTP，结束清理；没有杀淘宝。

|次序|结果|请求耗时ms|缓存年龄ms|
|---|---|---:|---:|
|1|degraded / a11y_timeout|2131|790896|
|2|正常响应形态，无降级字段|952|未知（未返回）|
|3|degraded / a11y_timeout|2166|4118|
|4|正常响应形态，无降级字段|1114|未知（未返回）|
|5|degraded / a11y_timeout|2163|4122|

结果：3次降级、2次正常形态、0接口错误。第1→2、第3→4都在后一次读取恢复正常形态；第5后没有再读，不能计为后续已恢复。第1旧缓存年龄790896ms，正常读后下次降级年龄4118ms，说明期间缓存确有刷新；不据此声称所有缓存/树滞后根因已消除。

末端截图与正常读首屏8条名称/配额相符（好物沉浸看1/5、逛爆款好物抵扣快闪0/1、搜一搜0/5等），进度9/20、余额1430。没有滚动，所以本轮不证明滚动后的树视口刷新，也不将正常响应无年龄视为绝对新鲜保证。

结论：有限等待重读是有效候选，比首次降级立即视觉补读有节省机会。建议未来只对只读查询限次重试，达到正常形态后继续核对当前页面身份与目标；不将此策略用于点击/领奖等动作重试。当前仅诊断probe，未修改正式业务策略。

本轮未使用Midscene，父Agent事后看截图仍有视觉消耗。forward与8080/8081监听清理读回均空。未动收益账、调度、无障碍配置。
