# LOOP职责与AI、脚本边界

状态：用户已确认，实施中；实现与验收见《下一步LOOP实施与验收-20261103.md》。用户在本方案后回复“我认为没问题”，批准按本LOOP替换每项任务前完整采集再全局规划的主线。

## 核心设计

程序管理循环与真实状态，AI补当前页面中代码无法确定的业务判断，脚本执行已学的有条件流程，底层执行器统一发送设备动作。AI不是单独跑一条流程，也不直接拥有设备派发权限。

可固化的不仅是打开应用和单项任务动作，还包括：循环调度、尝试历史、一次派发防重、任务状态转换、收益记账、日志目录和最终收尾。不能固化成固定坐标或假设页面永远不变。

## 状态与职责

|阶段|程序/脚本负责|AI何时判定|
|---|---|---|
|进入活动列表|调用已学入口流程，验证当前检查点|入口变化、弹窗、无法确认当前页面时，判断当前下一步|
|寻找下一项|提供当前截图、范围、历史尝试和流程能力；执行滚动或选中动作；检查次数、防重|当前任务列表的业务选择默认由AI：第一合格任务是谁、要求是什么、走什么已学流程、下一步点哪里。仅在已有当前证据足以等价判断时才由代码替代|
|执行选中任务|复用对应流程，执行能确定的连续步骤；持续记录结果|没有对应流程或脚本遇到未覆盖状态时，AI判断下一步/下一段，并更新条件计划；超范围则停|
|任务完成与返回|已有明确回执规则可由脚本识别，保存证据，按当前证据返回列表|回执语义不清、返回路径变化时AI判读；AI一句完成不代表收益已入账|
|核账与状态更新|校验所属资产页两张新帧、计算变化、区分额外收益、SQLite保存与读回；更新历史|仅当视觉余额/回执/归属语义不明确时辅助读取；不能让AI凭推算补出收益|
|继续或结束|选下一项循环；无候选时继续逐屏查找；覆盖顶部到底部后才结束；返回桌面/息屏|AI判断当前屏是否有合格候选及是否到边界；程序结合实际搜索覆盖记录判断是否允许结束|

## 建议循环

进入列表 → 获取当前观察 → 脚本/AI决定下一步 → 校验该步范围与当前目标 → 持久化意图 → 执行动作或已学步骤段 → 观察结果 → 更新状态 → 继续。

任务列表决策可返回“选择任务”“继续向下查找”“没有剩余候选”“阻挡停止”。选择任务时附身份、真实要求/次数、基线、执行流程引用或条件计划和当前动作。不要求枚举全部任务、不要求其他行坐标。返回列表重新观察位置，已执行记录保留；若要求从顶部首项顺序，先回到当前顶部再逐屏寻找，找到即执行。

任务内的同一循环可推进多个已知步骤，不必每一点击都调用AI。真实要求连续滑动时执行有限连续动作段，段内不插慢模型读图。脚本未覆盖、页面有歧义或证据不足才回到AI判断；未知输入不得重放或让AI绕过。

## AI与脚本共同的决策接口

NextDecision包含：当前page/phase、选择理由、task（仅需要时）、plan引用/更新、next（执行流程/点击/滑动/等待/返回/完成观察/停止）。程序执行后提供新的Observation与历史。AI输出是结构化业务决策/受支持动作计划，不是任意JS即时执行。返回任务列表后不使用旧坐标。

状态示例：寻找任务→选中未进入→执行中→看到完成回执→返回待核账→已确认收益/未确认→寻找任务。任务尝试状态与收益状态分开；失败已消费attempt，未结算不标成功，允许安全继续其他任务。

## 一项任务的例子

列表上AI选“浏览5秒”任务并引用浏览流程；程序持久化选中与派发，执行入口。浏览脚本确认落地页独立浏览要求并按已学方法完成。若出现新引导，由AI补当前一步，再由程序执行。明确回执出现后程序归档、返回、核账，记录结果。新截图进入下一项选择。一次入口与连续浏览段不反复让AI重新决定。
