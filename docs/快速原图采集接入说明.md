# 快速原图采集接入说明

状态：独立模块与离线注入测试已实现；未连接设备、未实测采图速度、未接入正常入口。

`RawCapture` 位于 `runner/staged/raw-capture.ts`，只有 `captureBurst` 和 `deriveFrames` 两个观察方法。没有 tap/act、frame 消费注册或动作 authority。调用方必须在原有共享 device lock 内完成动作、采图与后续检查；每台设备必须复用同一个模块实例。内部 busy 门禁只保护这个实例，不替代跨模块/跨进程共享锁。

```ts
const raw = new RawCapture({ serial, evidenceDir });
// 以下位于调用方持有的共享锁作用域内，且动作已由原 dispatcher 发出。
const batch = await raw.captureBurst(
  { package: 'com.taobao.taobao', userId: 0, taskAttemptId },
  { frames: 8, intervalMs: 250, budgetMs: 2000 },
);
if (batch.status !== 'complete') {
  // 有效部分帧保留为证据；调用方决定停止或检查，不能重发 claim。
}
const frames = await raw.deriveFrames(batch,
  { ocrBinary: '/Users/mater/.hermes/cache/scratch/checkin-apple-ocr' },
  { budgetMs: 2500 });
// 再逐帧运行原有 panel-claim validator；owner.now 必须取实际当前时间。
// 这些观察不注册 device.currentFrame；不能直接作为 tap 权限。
```

生产采图只运行 `adb -s <serial> shell dumpsys activity activities` 与 `adb -s <serial> exec-out screencap -p`。每帧前后校验 resumed activity 的 package 和 Android user，任一缺失、歧义或不匹配即停止。捕获时间取 screencap 调用前的宿主时间，是保守的采图开始时间，不声称是 Android 渲染时间。两端身份相同不能排除中途切换再返回，仍须共享锁隔离其他调度者。

最多 8 帧、总采图预算最多 2000ms；interval 是从整批开始计算的目标时间间隔，ADB 较慢时不会并发补采。每次执行、等待和落盘都受剩余预算约束。超时不补时间、不合成帧、不伪造新鲜度。调用方可注入 `exec` 和 `{ now, monotonic, sleep }`；生产默认使用 execFile Buffer 输出、剩余时间 timeout 和 SIGKILL。若注入器不响应超时，调用仍按时返回，但 busy 保留到后台操作真正结束，调用方不应据此提前放开共享锁供其他设备操作使用。

采图期间只检查 PNG 头与大小，保存独占创建的 PNG 和 `.raw.json` sidecar；两者不会由本模块覆盖。sidecar 固定 id、batchId、owner、capturedAt、尺寸、路径和 PNG SHA-256，不含伪造的空 lines。写入失败或超时可能留下未返回的孤立证据文件，不能把它们当作有效帧。

整批采完后 `deriveFrames` 才读取文件、核对哈希与 sidecar、用 sharp 完整解码，然后一次调用本地 OCR 二进制：`<binary> <output-json> <png1> ... <pngN>`。返回格式须为 `{ pages: [{ file, width, height, lines: [{text,bounds}] }] }`，每张图唯一对应且 lines 非空、坐标合法。也可注入批量解析函数 `(frames, {timeoutMs}) => Promise<该格式>`；测试中的文本为注入协议夹具，未声称实际 OCR 识别成功。OCR 结果及派生帧保存到独立 `.derived.json`，来源写入 `page.rawCapture`，原图 sidecar 不修改。

派生预算最多 5000ms，实际受整批最早帧的 5 秒新鲜度进一步约束，超时或任一帧过期即整批拒绝，不把 parsedAt 写成 capturedAt。整批严格策略可能丢弃仍新鲜的后几帧，调用方须把失败作为明确观察阻塞。

**当前接入限制：** panel-claim 同时要求 1080×2400 原图、有效非空 OCR lines 与实际当前时刻下的 5 秒新鲜度。独立 raw burst 返回值不能直接冒充 DeviceFrame。若实际整批解码+OCR无法赶上最早帧的 5 秒窗口，现有 validator 下仍然阻塞，不能复用旧 OCR、返回空 lines 或延长 capturedAt。需要独立测量后再决定如何接入；本交付未改 device/runtime/main/config/script-validation，也未证明手机上的 8 帧/2 秒性能。

## 控制器两阶段依赖

`controller-runtime.ts` 已新增 `captureRawBurst(request)` 与 `deriveRawFrames(batch,{budgetMs})`：采集阶段单独限2000ms，之后解析最多3000ms且还受原帧5秒期限约束。派生结果必须逐帧保留原id/path/capturedAt；超期停止，领取intent已消费不重发。旧captureBurst/captureTransient接口保留。父TDD真实panel PNG/engine回放先缺依赖失败，再以采集后2200ms解析通过、5100ms晚到拒绝；raw/panel/controller相关14/14、staged类型通过。此为注入时钟离线验收，未声称真实USB采集或OCR时延已达标，尚未接入main/runtime。
