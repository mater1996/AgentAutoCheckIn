# 到访与逛店候选脚本实现

依据 `已学任务稳定脚本验收方案.md`、`历史已学任务脚本缺口.md` 第128与138项及其原始历史合同。本次仅新增两个本地候选执行控制器、两个测试文件和本文。没有修改 runtime/checkers/observations/device/模型/账本，也没有新真机验证。所有合同固定为 `candidate`。

## API 与调用边界

```ts
const contract = await buildPanelClaimContract(projectRoot);
let state = createPanelClaimState(contract, taskAttemptId, balanceBefore);
const plan = await planPanelClaim(frame, {
  package: 'com.taobao.taobao', userId, taskAttemptId, now: Date.now(),
}, state);
// runtime 必须在派发动作前持久化 nextState，保留 intent 即已消费；
// 派发成功、失败、结果未知都不能重置为 ready。
state = plan.nextState;
// 有 action 时 runtime 使用当前帧权限派发一次，再取不同的新帧。
```

`planPanelClaim(frame, owner, state)` 与 `planShopBrowse(frame, owner, state)` 是无设备/模型/写入副作用的异步规划函数：只读原PNG与源文件，返回动作建议、回执、下一状态或明确未知原因；不会自行执行动作。state 由调用者持有，输入不被修改。`owner.now` 由 runtime 提供，帧须属于当前 package/user、年龄不超过5000ms，attempt 必须与 state 一致。runtime 仍负责独占锁、一次消费、当前选中任务授权、动作结果归档、阶段期限、稳定余额及账本。

合同由真实历史来源产生，包含原 result/OCR/PNG 路径和 SHA256，版本摘要覆盖合同字段，每次检查重新核验源字节。页面检查实际解码1080×2400 PNG，通过空间OCR及16像素小块图像组件匹配，不能只凭JSON描述、OCR关键字或任务消失通过；图不可读、尺寸错误、遮挡、错用户、错attempt、错页及源hash失配均停止。

公共只读图像/历史适配帮助函数位于 `runner/staged/panel-claim.ts`，逛店模块复用这些函数，不依赖正在开发的 dwell 适配层。`readHistoricalFrame` 的 `page.historicalReplay` 保存原PNG/OCR引用、hash、原capture时间和原observationError。136的90089616帧原flattened lines为空并记有 `OCR capture failed`；派生回放使用同帧另存原raw OCR，原失败仍明确保留，原文件没有改写。派生帧不是新采图，不能拿来派发真机。

## 到访128：同面板一次领取

`buildPanelClaimContract`、`loadPanelClaimReplay`、`createPanelClaimState`、`planPanelClaim` 为对外API。状态为 `ready → awaitReceipt → awaitStableBalance`。

- `ready` 要求面板“赚金币抵钱”、唯一完整原当前行 `任务到访得金币(0/1)`、`每日来任务面板币+10`、`领取奖励`，并核验原组件位置与PNG。返回当前OCR中心点一次tap建议，同时进入已消费状态；原图已带toast时不会新发领取。
- 建议快速采图预算为8帧、250ms间隔（2秒采图窗口，覆盖历史frame-2到frame-3的实际延迟）。runtime 应快速保存raw PNG，避免串行模型/OCR等待漏掉瞬时回执。控制器不执行采图，回执观察上限为入口后5000ms。
- `awaitReceipt` 要求同attempt、不同且更晚frame、原当前行仍可唯一核验，并用当前raw PNG匹配源frame-3中央toast组件 `[270,930,810,1140]`。源OCR未包含toast，没有补造OCR；quote `任务完成！获得10淘金币` 来自128原result的视觉审计及对应原PNG。回执记录当前frameId、capture时间、当前PNG SHA256、attempt、method和源result路径/hash。
- 原按钮仍显示、旧余额1430、任务替换或后帧余额1440，均不会触发第二次tap。只观察到任务替换却没有toast时是unknown，不能补造回执。超时为 `needsLearning`，原领取仍消费。
- `awaitStableBalance` 仅返回 `observe`，保留已确认回执，交由runtime取得正确活动的正收益稳定余额后结算；单个1440帧不算稳定。纯控制器不伪造settlement完成。

到访仍缺：新会话快速采图采样可靠性、toast在其它字体/布局/位置的合同，以及同hash两次正常入口零模型验收。当前模板只支持原证据约束内组件，变化返回unknown。

## 逛店136/137/138：独立多层路线

`buildShopBrowseContract`、`loadShopBrowseReplay`、`inspectShopBrowse`、`createShopBrowseState`、`planShopBrowse` 为对外API。状态为：

`ready → awaitShopList → awaitStore → awaitStoreReceipt → awaitShopListReceipt → awaitActivity → awaitSettlement`。

`awaitStore` 若已看到完成组件，可直接跳到 `awaitShopListReceipt`，不额外手势。

- 外入口当前唯一任务 `逛好店赚一大波金币(0/1)` 与独立说明 `浏览15秒`、按钮绑定，给一次tap。跳转未确认时保持原入口消费，拒绝历史第二次旧坐标tap。
- 店铺列表通过 `逛好店得金币`、可变推荐家数、真实按钮组件识别；从当前卡标题、当前按钮与同组件 `+10` 唯一配对，不写死店名。`inspectShopBrowse` 返回可选 `cards`。有多个fresh卡而调用者尚未选择时返回 `needsLearning`；runtime可从本帧cards选择一个 `name`，写入 `selectedCardName` 再规划。只能匹配当前唯一fresh按钮，不能点“再逛逛”。
- `selected` 保存实际所选卡名称、frame、capture时间和PNG hash。进入“浏览送金币”子页后必须匹配当前所选名称及顶部独立“滑动浏览 +10”或真实“浏览完成 +10”组件；不要求子页复述外任务全名，不因外列表20与子页10不同误拒归属。
- 店内手势的完整历史无干预成功序列不足。默认 `needsLearning`，明确缺失gesture sequence。只有显式设置 `learningBudget: { status: 'candidate', maxGestures, gestureMs, observationBudgetMs }` 才建议候选swipe：maxGestures为1至5，gestureMs为200至1500，observationBudgetMs为1至20000；每次建议即消耗一次，随后要求不同新帧，超预算继续 `needsLearning`。固定中部内容区域swipe是新增候选学习动作，不能声称历史已学配方或自动verified。elapsed不产生回执。
- 子页真实 `浏览完成 +10` 后给一次back；返回店铺列表必须看到右下 `任务已完成/继续逛逛吧` 真组件，且原所选卡变“再逛逛”，才给第二次back。仅子页完成或提前返回活动均不能跳过层级。
- 回到正确活动后只进入 `awaitSettlement`，runtime继续核对正收益稳定余额；不从30猜20+10拆分。

来源：136为原动作attempt；137是同一 `1a8dc6f9-64ba-4e17-9bcd-8f429eaa9ef6` 的恢复，误拒了子页10回执；补返回目录提供6eaca3f5子完成、ea827ed1店铺列表完成与5976ebdb活动帧；138为监督恢复结算，`automaticRunnerAcceptance=false`。回放显式 `historicalEntryOwnershipVerified=false`，不会把136第二次tap与特定进店卡归属当成已证明。回放沿当前卡绑定演练候选状态转换，并非重建已验证历史动作序列。

逛店仍缺：正常单次外入口到已选卡的无歧义真机执行、店内手势参数学习、跨新会话的完整两层返回及稳定收益验收。预算只约束新学习，不改变这些缺口。

## 实际离线验证

两个测试文件读取原PNG/OCR并真正调用上述状态机与checker，不连接手机、不调用模型。正例覆盖128原入口、漏OCR toast和返回面板，以及136/137/138的五层页面链。负例覆盖旧帧/错attempt/错用户、重复任务行、无效PNG、原OCR配错PNG、完成推广金额替换、真实图局部遮挡、多个当前店铺入口、错所选店铺、越层返回、重复派发和学习预算耗尽。测试中的局部遮挡图及同图新时间帧为明确派生负例/预算检查，不是新session验证。
