# 淘宝入口导航：踩坑与最终方案

> 2026-10-30 实测记录。这份文档只讲一件事：**怎么稳定地把手机从任意状态带到淘金币任务面板**。
>
> 入口是整套系统里最容易失效、也最容易烧钱的一环——失败一次实测烧 17 万 tokens（run #22），
> 而一次真实任务执行只要 ~7,000。所以入口必须 0 调用、纯本地。

---

## 一、最终方案（已验证）

```
① am start -W -S         强制停止后干净启动 → 淘宝首页
② tap_text「我的淘宝」     底部导航最右，content-desc 可读
③ tap_text「领淘金币」     我的淘宝页图标行，content-desc 可读
④ 滚到顶 → 等1秒 → 连点两次「去赚金币」   游戏页 Canvas，只能坐标
⑤ read 余额              唯一一次模型调用
```

实测输出：

```
↳ 本地点击「我的淘宝」(972,2203) clickable=true → 0 调用
↳ 本地点击「领淘金币」(866,419) clickable=true → 0 调用
↳ shell: input swipe 540 600 540 2000 300; sleep 1; input tap 120 1040 ×2
```

**前 4 步 0 模型调用。** 第 5 步读余额是必须的（要用它判断有没有真赚到）。

## 二、为什么走「我的淘宝」而不是首页图标区

试过三条路，只有第三条稳定：

| 路径 | 结果 | 失败原因 |
|---|---|---|
| 首页图标区「领淘金币」固定坐标 | ❌ | 图标行 y 位置随活动 banner 漂移，实测两次冷启动差 **180px** |
| 首页图标区 + AI 视觉定位 | ❌ | 模型定位是对的，但**热区和视觉中心不一致**（中心 y=404，热区 y=390），点上去落空 |
| **我的淘宝 → 领淘金币** | ✅ | 页面稳定：图标行位置固定、不会自动跳转 |

**首页的问题不只是坐标漂移**，更致命的是它**自己会跳走**：

```
冷启动 0-5s   开屏广告
5-8s          首屏渲染
~10s          自动跳转到「天猫小黑盒」活动页 + 抽奖弹窗
```

所以首页只有 **6~9 秒的操作窗口**。等太久（比如等 10 秒保险）反而点到广告页——这就是「等了更久反而更差」的原因。

## 三、六个必须记住的坑

### 坑 1：`screenNodes()` 的联合正则会吞掉 `content-desc`

**症状**：淘宝首页 dump 出来只有 1 个节点，误判为「全 Canvas 渲染，无障碍树不可用」。

**真相**：淘宝节点普遍长这样：

```xml
<node text="" content-desc="我的淘宝" clickable="true" bounds="[864,2129][1080,2276]">
```

联合正则 `(?:(text)|(content-desc))="([^"]*)"` 会**先匹配到空的 `text=""`**，把后面的 `content-desc` 吃掉。

**修法**：按 `<node ...>` 逐个解析，分别取 `text` / `content-desc` / `bounds` / `clickable`。

修完后首页读出 **76 个节点**，包括：

```
我的淘宝: (972,2203) clickable=true
领淘金币: (866,419) clickable=true
购物车:   (756,2203) clickable=true
```

**这条推翻了我之前「淘宝首页全 Canvas、读不到」的结论——那是解析 bug，不是平台限制。**

### 坑 2：同一个入口有 3 个同名节点，只有一个可点

```xml
<node content-desc="领淘金币" clickable="false" bounds="[778,327][954,511]">   ← 外层容器
<node content-desc="领淘金币" clickable="true"  bounds="[778,327][954,511]">   ← 真正可点
<node content-desc="领淘金币" clickable="false" bounds="[792,461][940,507]">   ← 文字
```

不区分 `clickable` 会点到不可点的那个，表现为「点了没反应」。

**修法**：`findNode()` 优先筛 `clickable=true`，再按面积降序（取最大那个）。

### 坑 3：`am force-stop` + `am start` 会恢复旧页面

**症状**：以为冷启动了，实际停在天猫小黑盒抽奖弹窗。

**修法**：用 `am start -W -S`（`-S` = 先强制停止再启动）。实测 1.7 秒到 `TBMainActivity`。

### 坑 4：游戏页有动画，`uiautomator` dump 不出来

```
ERROR: could not get idle state.
节点数: 0
```

**修法**：游戏页只能用坐标。且必须**滚到顶 → 等 1 秒 → 连点两次**：
- 游戏页自己会滚动，不滚到顶按钮位置不准
- 有动画，单次点击常被吞

### 坑 5：任务列表每次都变

同一天三次进面板：

| 次数 | 任务数 | 变化 |
|---|---|---|
| 1 | 8 | 好物沉浸看 / 双11来淘金币逛买更省 / ... |
| 2 | 8 | 新增「头条极速版刷视频」，顺序全变 |
| 3 | 8 | 名字又换 |

**所以坐标必须按「行号」索引，不能按任务名。**

```json
{
  "task_rows": [[0.876, 0.343], [0.876, 0.433], ...],
  "row_pitch": 0.0829
}
```

`inventory.tasks` 是模型从上到下读的，顺序 = 页面行序，`index` 直接对应 `task_rows[index]`。

### 坑 6：prep 配了 Activity 判定却仍按文本判，会按 3 次 back 把 App 退到桌面

**症状**：`prep: false 归位失败，界面无特征文本`，然后 App 被退到桌面，entry 从零开始。

**修法**：
- 配了 `entryActivityAny` 就只用 Activity 判定，不退回文本
- 这类平台**跳过 P4 的 back 归位**（归位交给 entry 的 `am start -S`）
- 最终判失败时，只要目标 App 在前台就放行

## 四、成本对比

| 方案 | 每轮调用 | 失败时的成本 |
|---|---|---|
| `aiAct` 复合指令 | 6~20 次 planning | **175,458 tokens ≈ ¥0.35** |
| 单步 `aiTap` | 2 次 locate | ~15K ≈ ¥0.03 |
| **语义点击 + 坐标（现在）** | **0 次**（除读余额） | **≈ ¥0** |

入口失败一次的成本，抵得上 25 次任务执行。所以入口值得单独优化到 0 调用。

---

## 五、坐标失效怎么办

入口的语义点击（我的淘宝、领淘金币）**不依赖坐标**，平台改版只要 content-desc 文字还在就能用。

只有两个地方依赖坐标：
1. 游戏页的「去赚金币」(120, 1040) —— Canvas 绘制
2. 任务行的按钮（`task_rows` + `row_pitch`）

**失效检测**：entry 后 `read` 余额拿到 `null`，或探测拿不到进度 → 判 `NEEDS_HUMAN`，不进入任务循环，不烧钱。
