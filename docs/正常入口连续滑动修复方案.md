# 正常入口连续滑动修复方案

状态：待用户确认，尚未实现；本轮不操作手机、不修改执行代码、不启用调度。

## 问题与目标

执行152已进入商品浏览目的页，但模型返回滑动建议时，原截图超过15秒有效期，连续3次建议被拒，连续滑动实际执行0次。现有循环重新截图后再次请求模型，同样可能再次过期。

执行153的监督探针已经证明：精致面霜目的页连续16次900ms内容滑动，约16.8秒后显示“已得50”；返回正确活动后余额1600→1650稳定，到账50。一次监督成功不等于正常入口独立验收通过。

目标：让正常入口在当前页面条件确实满足时执行已学习的有界连续滑动，完整取得回执、返回、核验、记账和保存经验。保持截图有效期和收益门禁，保留旧失败记录。

## 拟采用的流程

以当前存在的一项未完成普通浏览任务为例：

1. 正常入口读取当前列表、排除已完成项目，按允许计划选择一项；唯一绑定当前任务行后进入。保存本次任务身份、入口动作、原始余额及尝试编号。
2. Agent看完整目的页，确认实际要求为独立持续滑动浏览，并指出安全内容区域及执行后预期。输出的是候选动作及适用条件，不能直接给过期坐标续期。
3. 模型返回后，程序重新截图。用经过历史成功证据与负例验证的本地页面检查器核对：前台包/user、尺寸方向、目的页与本次导航来源、奖励组件状态、内容区布局、遮挡和登录验证。重新在新帧定位内容区域，生成绑定新frameId的动作。页面条件与安全区域都能确认才执行；缺字段、OCR不可用、弹窗/布局变化或条件不明则拒绝，不把旧建议换frameId直接发送。
4. 首期只覆盖153已实际学到的持续浏览页面条件；其它页面保持原有学习路径。不能仅凭标题或“浏览10秒”一句文字判断适用，不能用固定坐标与相似名称强套。若本地无法可靠确认，保存两帧及原因停止；不无限循环“截图→慢模型→过期”。这项本地检查器的可靠性是本方案需要验证的内容，当前不存在现成已验证能力。
5. 使用现有连续滑动原语执行一轮：最多16次、每次900ms、总时长最多18秒。执行前给阶段预算预留完整滑动及观察时间；预算不足则不启动。每次检查前台包和user，异常立即停止。中间不插入等待、OCR或模型调用。
6. 立即截图读取真实完成/已得回执；没有回执不因为次数或时长达到上限认定完成。随后有界返回正确活动，读取稳定余额及任务状态，按原账本门禁记账。保存本轮经验、实际动作与候选脚本版本，不自动升级为已验证配方。
7. 清理并息屏读回，报告一项结果后暂停。

## 修改范围

- `runner/staged/engine.ts`、`contracts.ts`：增加显式“动作前新帧复核”接口及记录；旧提案、新观察、重新生成的动作分开留档。过期提案本身仍拒绝。已派发但结果未知的动作不允许借刷新重放。
- `runner/staged/runtime.ts`及独立页面检查模块：接入经过测试的已学习页面条件和新帧内容区定位，处理完成状态优先于滑动、预算不足、页面不匹配和有界停止。不添加按任务名称判断操作的分支。
- `device.ts`现有设备权限继续负责新帧有效期、前台核对和单次消费；只有确有缺口才改。连续滑动原语已有，不重写。
- 为本次验收保存独立配置、计划、证据和文档，旧入口、原失败记录、已完成次数不覆盖。

本地新帧复核不能证明业务完成，也不构成账号身份登录证明；它只决定当前这轮内容滑动能否安全开始。

## 验证与验收

先离线写失败回归再修改：

- 慢模型返回过期建议、当前页面条件仍一致：旧坐标不派发，新帧重新定位后只执行一轮。
- 同包不同页面、任务列表、弹窗遮挡、奖励已完成、布局/尺寸变化、OCR失败及身份不明：不启动滑动；已完成状态走回执核验。
- 预算不够、重复调用、已消费帧、未知派发结果：停止，不重复执行。
- 对153原始成功页面及历史过渡、任务列表和错误页面进行离线回放，不能仅用伪造文字证明页面检查器有效。
- 检查收益门禁和原有回归、类型检查；通过后再做一项真机。

真机从正常CLI启动，动态选择夜胶原/精选好物/抗衰老精华中当前存在且仍允许、未完成的一项；若当前均不存在，保存现场并停止，不用已成功任务凑验收。不使用监督探针补过关，不在中途修代码后把原运行说成通过。

通过必须同时满足：正常入口自行进入、连续滑动实际发生、取得本次回执、返回正确活动、稳定余额与状态核验、账本/经验存储和息屏清理全部完成。只有任务成功但结算或存档失败仍不算整条通过；所有成本、失败和人工介入如实报告。单次通过只标记一次通过，不能声称稳定。
