# Controller 路由适配说明

新增 `runner/staged/controller-route.ts`，尚未接入正常 `runtime.ts` / main / config / device / store / script-validation；未修改任何既有共享文件。没有设备操作、模型请求或真实账本写入。

## 调用契约

`createControllerRoute(config, deps)` 接收明确启用的候选集合：每项含 family、逐字 task.name/instruction、已封印 LocalContract，以及 shop 可选显式 learningBudget。配置同时绑定 sessionId、scope、package、budget。依赖为现有 ControllerDeps：observe、dispatch、captureBurst/captureTransient、persist、now；执行固定调用真实 runControllerStage，不能注入替身 controller。

父 stage 在正常任务选中后调用 `await route.stage(stageId, ctx)`。返回 null 表示本阶段或精确任务未匹配，可继续普通路径；有匹配但重复/合同 family 冲突会停止。ctx 需含 id、scope、task、taskAttemptId、balanceBefore，与 runActivitySession 的上下文兼容。

- open_task：持久化 route started 预约后，完整运行一次真实 controller；同 attempt 后续调用使用缓存。controller 自身仍在动作前持久化 controller_state。
- task_receipt：校验执行成功、实际合同版本、同 attempt、状态与回执一致，然后映射 session.receipt。panel 保留 quote/frameId/pngSha256/sourceResult，补 path/version。shop 两层分别补 path/version，顶层保留两层合并 quote、shopList frameId/path、taskAttemptId、version、layers、returnedToActivity，不推导金额。
- return_list：只 observe 当前 owning activity panel，用新鲜 scope/package/user、真实 PNG 标题组件校验；不发 back。即便 session 错误处理重入，也不会重新执行 controller。

原回执没有 path，必须从 result.stages[].events 中允许的 observed/controller_transient_receipt/controller_transient_observed 事件按 frameId 找到原帧。允许同一原帧的完全相同副本；同 ID 内容不同、缺帧、原图 SHA 不同或归属不同都拒绝，不猜文件路径。

persist 由调用者实现真实 durable 存储，必须处理 controller_state 和 controller_route_state。snapshot() 仅提供记录快照；重启需从持久化记录显式传入 initialRecords。started/unknown 记录不重放。执行、保存或回执/返回校验错误缓存 unknown，保存失败时保留内存 poison；磁盘完全不可用时无法保证跨进程落盘，因此外部持久化仍是接入口门禁。

## 后续接入与已发现限制

完整 settle 仍由父 runtime 负责；路由对 settle 返回 null。接入口还需把路由 receipt 同步进现有 runtime 内部 receipt/selected 状态，否则仅包装 stage 无法让旧闭包 settle 自动识别外部回执。

检查现有 observations.ts 时发现 stableSettlement 接受 delta=0（仅拒绝负值），与接入计划所述“净正收益”门禁不一致。本任务未修改该共享模块；正常入口接入前应由父任务补正与测试。这里也未验证真实 USB 快采 2 秒预算、正常入口两次独立真机复验或 stable 资格。
