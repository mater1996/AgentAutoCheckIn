# 安卓观察与路由现状审计

范围：只读现有源码、已存原始证据和文档；仅新增本报告。未运行 ADB、设备脚本、OCR、模型请求、测试或采集流程，未访问/写入账本。源码行号对应本次读取的工作区；历史实测只证明对应版本、页面和时点。

结论：已有截图外的结构化信息，且分阶段入口保存的 Activity 原始 dump 比业务帧丰富。当前缺口是没有把系统状态、控件树和业务检查点组成统一、可追溯的页面观察与跳转记录。历史旧树问题真实存在，但不能推成“安卓树永远不可用”；WebView DOM/URL 仍未证实可取。

## 2. 原始证据复核

**系统层确实比“只有 package/user”丰富。** 本次本地解析 `evidence/staged-2026-11-02T01-25-13-762Z/device-command-evidence/foreground-490c9ba8-f40e-48d3-b362-c77d12f067d7.json`，原 stdout 有唯一 topResumed、Task/ActivityRecord、Intent，且存在 Intent 的组件、data 和 extras 标记；报告不复述 URL、参数或 extras 值。该前台为 `com.taobao.tao.TBMainActivity`，task 246；另一已存会话 `evidence/staged-2026-11-02T00-59-48-815Z/` 的前台为 `com.taobao.themis.container.app.TMSActivity`，task 245。这推翻“淘宝所有页面恒为 Welcome”的绝对表述，但尚不能仅凭组件区分所有活动、列表和任务目的页。dump 包含后台历史记录，不能把任意 Intent 当当前页面 URL，也不能把 task 编号当业务任务 ID。

**首页入口有节点，旧结论必须限时限工具。** 原始 `evidence/appium-static-2026-10-31T14-53-40-295Z/home-1.xml` 有三个 content-desc 为“领淘金币”的祖先/子节点，其中同 bounds 的 FrameLayout 一项 clickable=true、一项 false，另有文字区域 View。说明当次 Appium 可读该入口；父子重复需折叠，不能用三个节点当三个入口，也不能只看 text 判定不存在。实际一次 Appium clickGesture 未进入活动，读得到与点有效是两项能力（`docs/Appium静止任务列表读取实测.md:9`）。Portal 较早样本的入口不可点，也不能推广到该 Appium 样本。

**树覆盖与新鲜度必须按状态判断。**

- 本次解析 `evidence/portal-freshness-2026-10-31T09-18-30-815Z/sample-2.json`：714 节点，81 节点有非空 resourceId，原始 phone_state 明确有 TMSActivity、键盘和焦点信息。正常响应只有 a11y_tree/phone_state/device_context，没有捕获年龄；sample-1、sample-3 则明确带 a11y_timeout 降级及年龄。
- 本次重算 `evidence/appium-scroll-2026-10-31T15-00-53-762Z/{before,after-1,after-2,after-3}.xml` 的任务文字+bounds：四份均 8 行且摘要完全相同。既有事后截图核对确认视口已滚动，故该现场不可用旧坐标执行（`docs/Appium单次滚动读取实测.md:16`）。本次未重新调用视觉模型核图。
- 后续新 Appium 会话的默认/全部窗口/最上层窗口配置读到当前中段，但三配置任务行相同；12 个带次数节点只有 8 个完整可见，另有遮挡/裁剪。不能归功于窗口设置，也不能据此宣布跨滚动恢复（`docs/Appium窗口配置对照实测.md:17`）。
- 更晚整表实验的 `evidence/appium-inventory-2026-10-31T23-34-47-389Z/comparison.json` 明确 readerUnique=12、visualTotal=21、missing=9、complete=false，六次读树任务摘要只有一种；这是标题/次数覆盖，未验证完整奖励和按钮绑定。静止首屏成功不能代替完整清单验收（`docs/完整任务列表采集准确率实测.md:7`）。

Portal 0.7.30 的 2 秒门禁可回退最后成功快照，正常返回也可能复用较早在途读取。序列化完成/缓存年龄变新，不等于所有子树来自当前视口；背景变化同样不能证明任务区更新。现有证据定位到任务子树更新问题，尚不能判定淘宝提供层、Android/厂商缓存或时序中的具体根因（`docs/Portal快照新鲜度核查-2026-10-31.md:20`；`research/Portal滚动旧树源码定位-2026-10-31.md:21`）。

## 3. 当前正常接线没有统一路由观察

`runner/staged/main.ts:42` 实际构造 AdbOcrDevice，配置帧期限 15000ms；`:55` 按 controllerCandidates 启用 RawCapture。该入口没有引入 Portal/Appium 树。默认 `config/staged/taobao.json` 未启用 AI 面板等可选项；最近已存 run223 的实际 `config.json` 则是 localLaunch/localActivityNavigation/aiPanelReader=true、aiTaskRecovery=false，必须按会话配置区分，不能把默认配置或某次历史方案当全部生产现状。

普通截图前后只比 package/user（`device.ts:240`、`:255`），动作前也只比这两个值（`:318`）；同包同 user 内 Activity/task/弹窗/页面变化不会被该层发现。capturedAt 是 screencap 开始前的保守时间，前台 dump 和截图不是原子快照。普通 device 默认期限是 5000ms，staged 传入 15000ms；raw 派生仍严格保留原时间并限 5000ms（`raw-capture.ts:76`），不能统一声称“全系统都是 5 秒/15 秒”。

Portal 组合模块仍存在，但 `portal-hybrid.ts:40` 每次观察都会截图并调用 vision.query，之后才比较树行与视觉行（`:53`）；rowSource=portal 不等于没调用模型。`portal-observation.ts:43` 的独立新鲜度门禁也不是 Hybrid 的实际调用链；后者采用自身截图、帧期限、行比较和包名检查。`portal-collection.ts:68` 可保存完整 observation 和 PNG，但没有汇入 staged 的统一观察模型。

现有业务阶段并非空白：`session.ts:23` 有打开 App→进入活动→打开列表→采集→选择→打开任务→回执→返回→结算；`contracts.ts:13` 有 scope、previous/expectedCheckpoint 和 taskAttemptId；`engine.ts:69` 保存观察，`:131` 消费动作授权，`:171` 保存重新定位，`:194` 保存阶段结束。`runtime.ts:652` 绑定任务入口帧/动作/attempt，`:707` 绑定同 attempt 回执，`:752` 写 stage_event；`:174` 写 runtime.jsonl。`store.ts:148` 保存 stages/reviews/result。

但业务 stage 是“打算做什么”，系统 Activity 是 Android 组件，两者均不能代替“当前实际页面”。目前没有标准字段记录观察到的 pageKind、系统组件/task、当前窗口、树新鲜度、来源与判定理由的组合，也没有统一 before→action→after 跳转记录。run223 只完成 open_app，在 enter_activity 停止；其 final.json 的错误字符串提到 open_list，不代表实际已执行到 open_list，阶段应以 stages.json 为准。

历史像素策略仍在当前导航里：`activity-navigation.ts:124` 的 landing 要求文字布局和七块像素区域；`:156`、`:195`、`:198` 的 home 仍要求七锚点位置与历史组件匹配。任务面板分支 `:105` 已用当前文字/布局、原 OCR 和 PNG 格式确认，不要求参考像素。不能将整条导航统一描述成“已改成文字路由”，也不能将当前阻塞简单归因于 OCR 读不出。

## 4. 可怎样组织原始记录（建议，尚未实现）

保留两条关联轴：业务为应用→活动定义→任务定义→版本化过程；账号为账号→任务实例→观察快照→决策/执行→回执与收益。Android Activity/task 是观察证据，不是上述业务层级。当前 `store.ts:197` 已按业务 scope、名称和要求生成任务定义，providerTaskId=null；`:203` 将账号快照、计划、执行关联，并明确 partial inventory、positionAuthority=false。旧分层文档所写“尚未自动接入”不能覆盖这段更新代码，但其“无平台稳定 task ID”限制仍成立。

建议每条页面观察记录：observationId/frameId、session/stage/taskAttemptId、采样开始/结束、包名+user、实际组件/task（未知为 null）、窗口与坐标空间、pageKind/页面锚点、阻挡项、各字段来源和新鲜度、原始文件引用。把已存 dump 先作为可追溯旁证，不倒填成当年执行器实际使用过的字段。node path 只在所属观察中有效；页面改变或滚动后作废坐标。

建议每次跳转记录：源观察→动作意图/实际派发及时间→目标观察→预期与实际检查点→成功/未达/效果未知，绑定入口动作、回执和原始证据。可复用现有 stage_event、entryActionId 和 taskAttemptId，不必从零重造执行日志。device-command 未来宜显式关联这些 ID；历史没有唯一链接时保留时间区间与歧义，不能硬配。系统栈只能帮助解释返回路径，不能替代逐步返回后的实际页面验收。

Intent 建议仅提取必要且脱敏的 action/component、URI scheme/host/path 类别、是否存在 extras 等白名单字段；原始 dump 留在私有证据，查询参数、token 和账户数据不进入共享经验。还需区分当前 resumed 记录与后台历史记录。单个 base Intent 或 manifest deep link 只证明入口声明/启动意图，不能重建应用内部所有跳转或等同实际当前 URL。

供应商还有潜在补充：已有存档 Local API 列出 deep-link discovery/resolve/open（`research/evidence/Portal配置核查-2026-10-31/docs/local-api.md:72`），WebSocket 文档列出 APP_ENTERED/APP_EXITED（`research/evidence/Portal配置核查-2026-10-31/docs/websocket-events.md:58`）。当前 PortalHttpClient 未实现这些端点/订阅，也没有本机验收；App 进入/退出事件只给包名等信息，不是应用内部业务路由流。不能仅凭该供应商能力宣称平台已有连续路由监听。

## 5. WebView 与未来仍需实测的边界

已有唯一明确 socket 线索来自 `evidence/appium-static-preflight/preflight.json` 的 webviewSockets：浏览器调试 socket；`awake.json` 的进程列表将对应 PID 归于 com.android.browser，当时淘宝只有 channel 进程。它不能证明淘宝可调试，也不能证明淘宝永久禁用调试（`docs/Appium静止列表对照预检.md:9`）。

本次在 docs/research/probes 定向查找未发现淘宝成功 getContexts、CDP attach、DOM、JS 路由或当前 URL 的本机结果。已安装 Appium driver 文档确有 `mobile: getContexts`，根据 CDP endpoint 提供映射（`tools/appium-static/node_modules/appium-uiautomator2-driver/README.md:1185`）；这是供应商能力。淘宝相关页面能否暴露调试入口、具体使用的内核/子进程、可否读 URL/DOM、内页切换能否持续追踪，均未验证。无障碍树里的 WebView 类名或焦点类名不构成 CDP 可用证明。

未来若另行授权验证，优先回答：哪些页面的树在切页/滚动后仍与原图一致；首页重复节点怎样绑定唯一入口；系统组件/task/窗口字段在当前 ROM 上的稳定性和采样成本；WebView 调试入口是否实际属于目标 package/user；事件或 Intent 能覆盖多少业务跳转；同图文字布局能否替代哪些现有历史像素门槛。每项应同时保留成功、旧树/缺字段、遮挡及效果未知样本。当前不需要再跑历史任务来证明这些审计结论。
