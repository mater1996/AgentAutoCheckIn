# 阶段观察优化实现（离线）

本轮已在真实 createStagedRuntime → engine.runStage 主线实现；未连接手机、ADB、真实模型、OCR、数据库或 cron。模型和新增 PNG 为明确合成测试；既有回归仅在 scratch 副本内消费已有资料。尚无 live 性能或收益结论。

## 显式开关与阶段行为

- `panelReadPolicy: 'focused-v1'`：要求 `aiPanelReader:true`、`scriptValidationMode:false`、`balanceComponent:false`。默认不配置保持 legacy。
- `taskObservationPolicy: 'current-components-v1'`：要求 focused-v1 与 learnedBrowse.enabled。runtime 选择当前组件检查 API，保留旧 API 默认。
- 既有 `aiTaskRecovery:true` 独立显式开启；focused 组合还要求现有 learned executor（sourceRunId=153）实际可用，不自动改业务配置。

| 阶段 | 读取/复用 |
|---|---|
| collect_list | 完整逐页 AI；必须真实 top/bottom，空 tasks 不得报告或持久化 complete=true |
| select_task | 优先复用尚有效、未被动作消费、通过当前哈希校验的完整面板观察；无可用完整观察时采新帧完整读表 |
| open_task 入口前 | 选中行仍唯一且 quota 完整相符时复用上一有效帧；过期、缺行或无法绑定时新帧 focused selected-row，仅按 name+instruction+done+total 重绑 |
| 动作后确认/settling | 总是新 capture；未给 engine 增加复用接口 |
| return_list | focused return-status：所属面板、余额及选中行状态；行消失不伪造 tasks，也不阻止确认回到列表 |
| settle | 每次 wait 后新 capture，focused settlement；两个不同 ID 新帧的正余额稳定增量、同 attempt 回执、可见 quota 不矛盾才成功 |

runtime 的 device Proxy 在任何 `act` 或 `scrollContinuously` 调用前使复用失效，覆盖普通 dispatch、等待、滚动、导航和 controller 的 runtime 回调；异常/未知效果同样不留可复用权威。控制器依赖自行绕开该回调操作设备不在 runtime 能约束的范围。复用保持原 capturedAt，不因新 stage 续期，沿用 15 秒 gate 与原设备派发前 owner 校验。收集最终页即使在底部也仅代表当前可见页；选择的有界滚动仍会产生新读取。

合成主线用例：收集→选择→入口只发生一次完整 AI 查询，选择和入口使用同帧；入口后 arrival/engine settling 各自取新帧；返回两次局部读取，结算两次局部读取。此用例不等于所有场景可固定只读一次，也不代表全消除截图或模型耗时。

## Reader API 和原始证据

未新增 focused-panel-reader.ts，沿用 ai-panel-reader.ts 内 schema/PNG/原始响应/manifest/hash/usage 校验，避免平行维护第二套证据加载器。

新增类型：

```ts
type PanelReadMode = {
  purpose: 'selected-row' | 'return-status' | 'settlement';
  task: {name:string; instruction:string; done:number; total:number};
};
readAiPanel({...existing, readMode?: PanelReadMode});
loadAiPanel(frame, expectedMode?: PanelReadMode); // 同步，只读磁盘，不调用模型
```

focused 原始响应必须严格为 `{isPanel,balance,blocked,taskStatus,task}`；taskStatus 为 visible/absent/ambiguous/not-panel。visible 必须有完整真实行；其他状态必须 task=null。行替换、错误 total、selected-row 错误 done、schema 或坐标错误拒绝，原始响应仍持久化。模型请求携带 panelReadMode（便于注入边界测试），真实 VisionClient 通过 prompt 内明确的 mode JSON 获得相同要求，不依赖客户端新增字段支持。

manifest 继续 `version:'ai-panel-v1'`，新增可选 readMode，将读取目的和任务身份一起强绑定原 PNG 与 frameId、capturedAt、owner。无 readMode 表示历史完整 schema。runtime 缓存键从显式 focused 策略下的 frame ID 扩为 `[frameId,readMode]`，失败缓存也不跨目的复用。同步 load 每次重核 PNG、manifest、rawResponse hash，expectedMode 不符返回 null。归一化 focused 结果 `inventoryComplete:false`，top/bottom=false；缺行永不从旧 selected 填入。返回/结算 purpose 即使含可点击的未完成行，validateProposedAction 也拒绝 tap。AI 不合法不回退 OCR 获得权威。

## 当前检查点与 AI 接力

runtime 按显式 taskObservationPolicy 调用其他子任务提供的：

- inspectCurrentDwellBrowse(frame,owner,contract)
- inspectCurrentLearnedBrowse(frame,owner,options)
- inspectCurrentImmersiveBrowse(frame,owner,options)
- selectContinuousContract(frame,owner,{}, {policy:'current-components-v1'})
- inspectSelectedContinuousContract(frame,owner,selected,{policy:'current-components-v1'})

对应注入点为 opts.inspectCurrentDwellBrowse / inspectCurrentLearnedBrowse / inspectCurrentImmersiveBrowse，旧注入点和 legacy API 默认保留。当前 immersive 返回 `immersive-browse-current-components-v1`，runtime 使用该检查版本，保留配置合同及奖励转换来源。

连续滑动的当前策略在 beforeDispatch 重采帧，通过绑定的同 attempt、同要求/奖励/版本与当前新帧检查，重新生成 swipe；不再掉回旧整页商品像素重验。保留单次连续段、选中合同预算及剩余时间要求。engine 仍执行 fresh-frame、动作 age/consumption gate。

接力沿用已有恢复边界：必须实际 dispatched entry、当前原图/owner/task/attempt/source entry action、未决动作与剩余预算完整；本地已知状态优先。未知状态才 AI 一次安全下一动作；新帧命中已知组件便回脚本。新增测试真实经过 engine 证明“未知加载页→一次 AI wait→已知完成态→本地回执”，没有重开入口或继续模型接管。未知派发不重发；敏感点击仍禁止。恢复中出现要求变更或新策略问题仍停止报告。

## 父整合接点（本子任务未改）

1. 独立 audit 必须复算新 focused schema 与 purpose+selected binding，允许 return-status 在真实 selected 行消失时确认列表，不把 tasks=[] 视为完整盘点；结算仍独立验 same attempt/两不同帧/稳定正增量。不能只看到 ai-panel-v1 就按历史完整表解析。
2. 审计当前组件 policy 与 continuous beforeDispatch 的当前检查/新坐标生成相同；保留 legacy 历史回放。复用事件 `observation_reused` 带原 frameId/capturedAt；engine observed 事件仍记录该原帧，不能推断新 stage 产生了新 capture。
3. main/source archive 无新增模块路径；仍需冻结本轮 ai-panel-reader/runtime/observations/config 与静态导入 checker 的实际字节；配置生成显式加 policy/recovery 开关。子任务没有修改 main、engine、contracts、script-validation。
4. 当前 immersive 的既有 ocrQuality 派生与 reward transition 模块仍是它们原来的独立路径，本轮未将它们整体重写成 current policy。启用组合时父须验证这两条的 policy 一致性，不把普通 current inspector 成功算作该异常分支验通。
5. runtime 只安全复用 collect→choose 和 choose→open_task 初始观察。return/receipt/动作后 engine settling 仍新 capture；不宣称已全消除重复读取。
