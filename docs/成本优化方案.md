# 成本优化方案 v1

基于 2026-10-30 九次真机运行的实测数据。所有数字都可追溯到 `run` 表与 Midscene 报告。

---

## 1. 问题定位（实测）

### 1.1 单次运行成本构成（run #20，唯一一次完整成功）

| 意图 | 调用 | tokens | 占比 | 单次均 |
|---|---|---|---|---|
| **planning** | **43** | **706,324** | **83%** | 16.4K |
| insight | 13 | 92,915 | 11% | 7.1K |
| locate | 7 | 53,784 | 6% | 7.7K |
| 合计 | 63 | 853,023 | 100% | — |

成本 ¥1.71，收入 ¥1.85，净 ¥0.14。

### 1.2 关键归因

**planning 43 次而 locate 只有 7 次**——说明绝大部分规划**没有走到执行**，而是反复重规划。

原因链：

```
每个任务单元 = 一次 ai()（复合指令）
  → ai() 内部先 planning（拆步骤）
  → 某步失败 → 触发 replanning（默认允许多轮）
  → 每次重规划 16.4K
  → 5 轮任务累积 43 次规划
```

**结论：不是任务太多，是每个任务都在让模型重新思考怎么做。**

### 1.3 为什么复合指令特别贵

任务单元当前写法：

```yaml
- do: ai
  say: 在任务列表里点击第一个「去完成」的任务；如果出现搜索框就输入「女装」并搜索；
       否则停留 15 秒并滑动一次；完成后返回任务页
```

一条指令含 4 个分支，模型每次都要重新判断走哪条，规划产物无法复用。

## 2. 优化方案：四层，按 ROI 排序

| 层 | 做法 | 每轮成本 | 17 轮总成本 | 净收益 | 风险 |
|---|---|---|---|---|---|
| 现状 | 每轮 `ai()` | ¥0.28 | ¥5.8 | ¥2.0 | — |
| **L1** | 换 `aiTap`（单动作） | ¥0.045 | ¥0.41 | **¥7.4** | 低 |
| **L2** | 固化坐标 | ¥0.005 | ¥0.15 | **¥7.65** | 中 |
| **L3** | 批处理探测 | — | 再省 ¥0.08 | ¥7.7 | 中 |
| **L4** | 止血项 | — | 防雪崩 | — | 无 |

## 3. L1：`ai()` → `aiTap()`（核心改动）

### 3.1 原理

Midscene 的动作分两类：

| 动作 | 是否规划 | 单次 tokens |
|---|---|---|
| `ai()` / `aiAct()` | ✅ 先 planning 再 locate | 16.4K |
| `aiTap()` / `aiScroll()` | ❌ 直接 locate | 7.7K |

**换成单动作后，planning 归零，重规划雪崩也就不存在了。**

实测印证：`probes/locate-coin.ts` 用 `aiLocate` 两次，3 次调用 23,153 tokens（无 planning）；而 `probes/probe-coin-page.ts` 用 `ai()` 一次，2 次调用 31,891 tokens。

### 3.2 任务分类（已改为「先收集，再决策」）

> **本节原始版本用"按任务名匹配规则表"，已被否掉**：名字只是索引，不等于"这个任务要做什么"，平台改文案就全错。
> 现行设计见 `docs/任务标准流程.md` 第 2~4 节：**收集（1 次调用拿全量清单）→ 决策（0 调用算可行性与跳过）→ 执行（按类型分流）**。

关键差别：

| | 名字匹配（已废弃） | 先收集再决策（现行） |
|---|---|---|
| 任务清单从哪来 | 边做边猜，一次只知道第一个 | **一次拿全 8 个任务、配额、按钮状态** |
| 能不能算"够不够跨档" | ❌ | ✅ 跳过拍立淘后可达 14/20，够不到 100 档 |
| 名字改了怎么办 | 猜错，静默失败 | 类型匹配不上 → 归入 default，并记录未识别任务 |
| 能否人工干预 | ❌ | ✅ 计划是 JSON，可审可改 |

执行阶段仍然按类型分流（浏览 / 小程序 / 搜索 / 相机），但**类型的判据来自收集到的 `name + button + quota`，并且分类结果写进计划文件，可事后核对**，而不是运行时临时猜。

### 3.3 收益核算

| 任务类型 | 每轮成本 | 说明 |
|---|---|---|
| 逛一逛（5 个） | ¥0.015 | 1 locate + 0 planning |
| 搜索（1 个，0/5） | ¥0.046 | 3 locate |
| 其他浏览（2 个） | ¥0.015 | 1 locate |
| 加权平均 | **¥0.045** | |

17 轮 ≈ ¥0.41，收入 ¥7.80 → **净 ¥7.39**。

## 4. L2：固化坐标（0 调用）

### 4.1 做法

首次运行时记录点击坐标（归一化），写入 `recipes/<account>_<activity>.json`：

```json
{
  "version": 1,
  "learned_at": "2026-10-30",
  "elements": {
    "entry_icon":     [0.50, 0.238],
    "daily_tab":      [0.972, 0.219],
    "earn_more":      [0.50, 0.260],
    "first_task":     [0.85, 0.42],
    "claim_button":   [0.36, 0.29]
  }
}
```

执行时先试坐标：

```ts
shell(`input tap ${x * W} ${y * H}`);   // 0 调用
```

### 4.2 失效检测（必须配套）

坐标会因改版失效。检测方式：**每 3 轮探测一次进度**，若进度未增长且坐标点击无反应 → 判定失效 → 清空该元素坐标，下次走 `aiTap` 重新学习。

```ts
if (progressStalled && recipeHitCount > 0) {
  invalidateRecipe('first_task');
  log('坐标失效，回退 aiTap 重新学习');
}
```

### 4.3 收益

17 轮从 ¥0.41 降到约 ¥0.15（只剩探测和入口）。

**但 L2 依赖 L1 先跑稳**——没有 L1 的 `aiTap` 做兜底，L2 失效时无路可退。

## 5. L3：批处理探测

### 5.1 现状

每轮结束探一次（7.1K），17 轮 = 121K。

### 5.2 改法

```yaml
objective:
  probe_every: 3        # 每 3 轮探一次
```

循环里计数，不到 3 轮不探测；靠 `collect` 的跨档判断兜底（跨档时才需要知道进度）。

### 5.3 收益与代价

- 省：17 → 6 次探测 = 78K ≈ ¥0.16
- 代价：卡死时多浪费 2 轮（约 ¥0.03）
- **净赚 ¥0.13**

## 6. L4：止血项（先做，防大额亏损）

| 项 | 改法 | 防什么 |
|---|---|---|
| 重规划雪崩 | `MIDSCENE_REPLANNING_CYCLE_LIMIT=1` | #17 烧 ¥1.05、#19 烧 ¥0.70 |
| 超时失控 | `MIDSCENE_MODEL_TIMEOUT=90000`（已改）、`RETRY_COUNT=1`（已改） | exec 1358s 超预算 50% |
| 起始页误判 | prep P5 断言加"首页独有特征" | 入口失败 3 次，¥1.53 |
| 探测口径 | 已改 JSON 一次调用（已改） | `6/20` 被读成 `0.35` |
| usage 解析 | 正则改为匹配完整 usage 对象 | 成本永远显示 0 |
| 跨页读数 | settle 先 back 再读（已改） | `after=20 < before=250` |

**这 6 项不改业务逻辑，纯堵漏洞，预计减少失败成本 70%。**

## 7. 实施顺序

| 步 | 内容 | 验证方式 | 预计工时 |
|---|---|---|---|
| 1 | L4 止血（6 项） | 跑一次失败场景，确认成本 < ¥0.3 | 40 分钟 |
| 2 | L1 换 `aiTap` + `task_rules` | 干跑验证规则匹配，再真机跑 3 轮 | 2 小时 |
| 3 | L3 批处理探测 | 17 轮完整跑，看总成本 | 30 分钟 |
| 4 | L2 固化坐标 | 连跑 3 天，看坐标命中率 | 3 小时 |

**第 2 步是分水岭**：做完之后单次运行成本从 ¥1.71 降到 ¥0.4 以内。

## 9. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| `aiTap` 定位不如 `ai()` 准 | 点错元素 | 每步后校验进度；连续 2 次失败回退 `ai()` |
| 坐标固化后改版失效 | 空点 | 每 3 轮探测，失效自动重学 |
| 批处理探测掩盖卡死 | 多跑 2 轮 | 硬上限 + 总时长闸门 |
| `REPLANNING_CYCLE_LIMIT=1` 降低自愈 | 偶发失败直接退出 | 失败后整体重试 1 次，而不是让单步无限重规划 |

---

## 10. 不做的事

- **不换更便宜的模型**：terra 与 sol 精度等同（实测偏差 0.031 vs 0.030），换模型省不了 planning 的 token
- **不做本地 OCR**：Canvas 渲染 + 动态布局，维护成本高于收益
- **不追求 0 调用**：探测必须调模型，¥0.15/天已经是合理下限
