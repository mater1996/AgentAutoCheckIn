# AI读图接入方案

用户已明确确认“那就让ai读呗”，授权实现此前展示的AI读图方案。替代任务面板中依赖OCR解析的任务名称/要求/进度/按钮/奖励/余额，普通动作仍由单一设备执行器派发。不是再为OCR增加同义词或像素模板。

## 实施范围

- 使用现有VisionClient，把当前同一帧原PNG交给配置的有视觉能力模型；每张图一次结构化读取，输出页面身份、阻断、top/bottom、余额、可见完整任务及对应按钮。要求原文、未知null、奖励区间与不同条件分开。闪购浏览20和下单最高1000不能混成同一浏览奖励。
- 持久化AI原响应、图片SHA、frameId、owner、模型名/版本及实际usage；原frame.lines、原PNG/OCR不覆盖。通过旁证接入readPanel，任务与余额来自AI，OCR可辅助现有执行合同但不再否决已经批准的AI面板数据。
- AI不直接操作设备，不凭名称猜任务执行方式；仍仅动态匹配已批准普通浏览计划，完整落地页合同、同attempt回执、正确资产页两次稳定余额及正增量才记账。读不清、非目标页面、风险提示、歧义停止并报告。
- scriptValidationMode的零模型标准不用于此新AI读取配置；保留旧配置/历史版本。新增明确AI读取配置，记录真实调用与消耗，不能把AI辅助叫纯脚本稳定。
- 模型耗时不延长原frame动作权限；超龄坐标不能直接点击。若现有15秒新鲜度与实测模型耗时冲突，先报告具体测量，不暗中放大阈值或重发动作。

## 验证与止损

先用run217保存的原图真实调用已配置模型，核对余额2265、庄园点击去逛+50、闪购浏览5秒+20/下单最高1000、课堂10~30。再测结构/范围/路径/证据篡改及实际runtime接线。无法调用或读错则报告实测，不用假输出替代。
