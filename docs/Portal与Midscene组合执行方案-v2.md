# Portal与Midscene组合执行方案 v2

日期：2026-10-31。状态：设计已获用户确认，通用模块第一步已完成离线验证（连接、任务行解析、单次动作门禁），尚未接入正式runner。实现结果见[第一步记录](../evidence/portal-adapter-step1-2026-10-31/implementation.md)。本步未操作手机，调度不变。

实施中补充：旧响应存在 `degraded=true`、`a11y_timeout` 和过期快照。第二步[只读新鲜度核查](Portal快照新鲜度核查-2026-10-31.md)确认Portal 0.7.30只给降级回退附年龄字段，正常读取不附。当前门禁的过度拒绝已在[正常响应适配](Portal正常响应适配-2026-10-31.md)中修正；缺字段不伪造为age=0，正常响应的动作另需当前目标核对。底层读取为何超时仍未定位，接受官方降级策略，不再为此阻塞后续采集接入。

## 1. 推荐结构

**一个业务计划、一个设备执行器，多个观察来源。**

Portal读取层级、焦点和键盘状态，并承担已验证的手势操作；Midscene承担必要的视觉理解、定位和受限探索；本地流程负责步骤、预算、结果核验及记账。OCR只补充层级无法表达的局部字段；ADB保留连接、启动、截图等设备管理能力。Mac投屏作为可选观察/诊断工具，暂不作为日常点击主路。

之前几乎所有事实和点击都经过视觉模型，今后让不同字段选择合适来源。任务列表可直接读取，不必问模型“每一行写什么”；复杂落地页仍交模型完整理解。Portal派发成功与Midscene说完成，都不是业务完成的充分证据。

不同时启用Mobilerun自主Agent和Midscene自主Agent规划同一任务。使用Portal现成服务即可，不必先安装整个Mobilerun Python框架；需要SDK时再对照其接入收益。

## 3. 工具分工与备选

| 工作 | 默认方式 | 何时用另一方式 | 明确不自动推导的能力 |
| --- | --- | --- | --- |
| 当前任务、配额、按钮 | Portal完整树＋局部解析 | 缺失/歧义时用截图与Midscene合并查询 | 树节点数多不代表真实前台正确或字段完整 |
| 输入焦点与键盘 | Portal phone_state＋输入字段读回 | 信息矛盾时检查截图 | keyboardVisible=true不等于目标输入框已有正确文本 |
| 业务理解与选择 | 已验证流程匹配；未知项整组评估 | 新实际说明/新落地页用模型 | 不按“搜/逛”等名称关键词猜流程 |
| 按钮定位 | 当前可见任务行的Portal节点bounds | 图形按钮用Midscene aiLocate | aiLocate返回rect可能为兼容框，不能当严格真实按钮边界 |
| 点击、滑动 | Portal手势，经统一执行器 | 仅显式诊断选择其他通道 | 不在Portal点击结果未知时立刻再用ADB/Midscene点击 |
| 余额等局部视觉字段 | 初期Midscene单次合并读取 | 后续OCR同图达标再替换相应字段 | 同模型重复读不是独立证据，OCR分数不是正确概率 |
| 页面身份、完成结果 | 页面前提＋Portal任务状态＋必要截图证据 | 树不含完成文字时Midscene结构化查询 | 不用泛“已完成”、按钮消失或等待结束当成功 |
| 设备准备 | ADB连接/唤醒/启动/截图 | Portal能覆盖的管理操作再按实测选择 | 不为“去掉ADB”迁移；Portal传输本身可经过ADB |
| 投屏 | 可选scrcpy辅助观察/输入诊断 | Portal仍不可靠再单独对照SDK/UHID/AOA | 不假设Mac窗口把Android节点导出成Mac控件 |

外部能力及官方原文沿用[Portal与投屏调研](../research/Portal层级与Mac投屏比较-2026-10-31.md)与[低消耗技术选型](../research/低消耗执行技术选型-2026-10-31.md)。本次另核对安装包的公共API：

- `@midscene/core/dist/types/agent/agent.d.ts`：aiQuery、aiLocate、aiAct可分别调用；aiLocate返回截图坐标center、dpr及rect，注释明确rect不保证严格边界。
- `@midscene/core/dist/types/device/index.d.ts`：AbstractInterface提供截图、尺寸、actionSpace、可选getUITree和动作前后hook等扩展契约。
- `@midscene/android/dist/types/index.d.ts`及`dist/lib/index.js`：当前AndroidDevice有getUITree和inputPrimitives，getUITree通过自身ADB捕获；并非已自动接入Portal。

存在扩展点不等于现成Portal适配器。第一阶段用组合调用验证成本和正确性，不先修改node_modules或为未知收益实现完整新驱动。

## 4. 如何组合，分两层推进

### 第一层：组合调用，先能验证

本地runner调用Portal取得观察；决定某字段需视觉时才调用Midscene aiQuery/aiLocate。aiLocate仅定位，runner验证前提并转换坐标后，由Portal执行一次。这样保留Midscene模型、报告和定位能力，同时避免aiTap默认走其原有输入路径。

**普通流程先不开放aiAct自主执行整条任务。**未知页面需要探索时，初期由监督模式逐步处理，保证每一步都通过统一执行与验证。如果使用原生Midscene动作，必须显式独占这一段并标明不同输入通道，不把它冒充Portal路线验收，也不与Portal并行。

截图读取不会自动命中runner的缓存：Midscene可能另取截图。组合时须记录实际取图时间，并在定位期间独占设备、确认布局未变。不能声称已做到“同一帧复用”，也不能把Portal JSON直接灌进aiQuery就假设Midscene会替代自身视觉路径。

### 第二层：确有必要再做设备适配

若第一层证明受限aiAct或统一取图有实际价值，再依据AbstractInterface实现Portal驱动：截图/size、支持的actionSpace和动作回调、UI树转换、取消与报告上下文。Midscene规划的每个动作才可统一交Portal，并在动作前后运行相同门禁。

这需要额外开发和对照测试。不能用简单替换方法、覆盖私有函数或修改node_modules保证兼容，也不能只替换tap就宣称输入、滑动、返回全部换通道。即便驱动完成，aiAct仍必须限制任务范围、次数、调用预算和停止条件。

## 5. 进程模型

```text
现有面板/API → SQLite任务队列 → 单一worker（持有手机锁）
                                   │
                     业务计划与步骤状态（唯一）
                                   │
                ┌──────────────────┴─────────────────┐
                ↓                                    ↓
        观察：Portal树/截图                 理解：已验证流程/必要模型
        字段来源与新鲜度                    Midscene terra视觉查询/定位
                └──────────────────┬─────────────────┘
                                   ↓
                      动作门禁 → Portal手势一次
                                   ↓
                    动作后状态 → 完成验证 → 账本/计划
```

Portal Android服务在手机端提供状态与手势；Mac worker通过本地传输连接。保留现有面板/worker分离及共享设备锁。不另建AI调度服务或第二套日常队列。

本地HTTP仅绑定/开放必要链路并核对服务实际设置，Mac通过ADB转发接入；token在私有配置或运行期内存，不进日志。现有试验每段临时启停HTTP，正式方案应在一批内复用会话，结束恢复本轮改过的状态并移除自己的转发，不能关掉用户原已运行的服务。Portal不可用时先报告具体错误，不无限切换输入方式。

## 6. 观察与动作统一规则

### 页面同步

1. 动作前核对真实前台与截图、任务身份、当前可见行及配额。
2. 动作开始即将旧目标句柄失效。之后树必须符合本步骤预期后条件，而非仅“又读了一次”。
3. 观察旧树时，允许有界轮询；首次建议至多3次、总计最多6秒，阈值待实测调整。连续两次相同树仍可能是旧树，不能据此单独判同步。
4. 预期页面未确认时，合并一次视觉判断；与树矛盾则保存冲突并停止依赖动作。相同Activity内切面板也必须检查页面身份。
5. 截图、树非原子同时获取，要记录各自时点和屏幕状态。动画不应强求整屏哈希不变，但相关控件区域必须稳定。

### 目标与坐标

每次使用新鲜节点，不把index/path持久当身份。任务行用公共祖先绑定完整要求、配额、奖励和按钮；当前精确文字可用于关联该次观察，不能跨天按名称相似硬匹配。屏外、遮挡、禁用、反向bounds或多个不明候选均禁止点击。

Portal坐标与Midscene截图坐标必须分别标明尺寸、旋转、缩放及dpr。先用已标注截图做变换对照，再做可逆入口真机验证；不能把aiLocate center未经转换直接传Portal。实际前提变化后坐标失效，不允许点击旧坐标。

### 动作与重试

每个动作关联action_id、attempt_id、观察ID、目标及预期结果。派发状态分为未派发、已派发待验证、效果成立、明确无效、结果未知。已派发待验证和结果未知期间禁止换通道重发。领取等可能不可逆动作，只有独立确认未生效且流程明确允许时才可重试；否则停止。

默认不把ADB tap作为Portal失败后的自动后备。通道故障调查单独进行，有新观察、明确上次效果和显式范围才改变通道。

## 7. 业务主线例子

以本次实际可见的“抢更多超级秒杀好物(0/1)／浏览5秒／+20”为代表，**以下目的页做法尚未由Portal组合路线验通，不能说它已稳定支持**。

1. Portal采集完整当前清单，包括当前面板、档位、要求和配额，滚动重叠采集并确认到底。完整树可能含屏外任务，但首轮仍需滚动核对；屏外节点不能直接作为可操作目标。
2. 已验证流程直接评估；未知任务与完整上下文整组交模型判断。不足条件标待学习。产出哪些做/跳过、原因、顺序、次数、预算与停止条件；不直接执行本例来代替任务选择。
3. 如果该条被计划选中，重新读目标行，确认实际要求和0/1未变，Portal点击其唯一对应按钮一次。
4. 等待页面同步，Portal先读目的页。如果实际要求含糊、图形内容或新流程，Midscene一次合并读取实际说明、完成方式、阻挡和可见目标。不能从列表“浏览5秒”直接假定等待就够。
5. 若已经验证的要求可由本地动作完成，Portal执行所需浏览/滚动，本地按明确要求计时；关键状态读取一次，不每秒调用模型。未知机制则监督学习，不自动无限探索。
6. 完成提示有树文本就用树；没有则Midscene读取完整提示。绑定当前attempt并保存原始证据，未出现则超时停止。时间到了不等于完成。
7. 返回正确任务面板，核对同任务计数、余额、档位。最后一次任务消失需本次回执等支持，消失本身不算成功。余额用拥有该资产的页面读取，滚轮文本用视觉补读；有歧义留未知。
8. 账本只记可信同口径净增，任务完成状态与收益分开；不能将+20显示值直接记收入。更新这条和受影响档位及剩余计划，批次末做完整核对，不每项都重扫全表。

目前用户要求每步汇报后暂停，这个执行模式保留为runner显式选项，不因换工具取消暂停点。无人值守调度保持暂停，需独立验收和用户确认。

## 8. 数据模型与配置（拟议）

保留现有run、account、activity、asset、gain_event及证据/配方，不先迁移数据库。先以版本化JSON记录，查询稳定后再归一化。

| 记录 | 必须保留字段 |
| --- | --- |
| ObservationBundle | observation_id/run_id/step_id；截图路径、尺寸与时间；Portal树时间/页面身份/前台；field_sources；freshness=confirmed/stale/conflict/unknown |
| TaskView | inventory_id/task_instance_id；名称与要求原文、quota、display_reward、行节点/按钮当前引用；完整性与歧义 |
| ActionAttempt | attempt_id/action_id/plan_item_id；before_observation、target、coordinate_space、backend、dispatch_status、after_observation、effect、error |
| WorkflowVersion | 适用页面与实际要求、动作/分支、完成合同、版本hash、真实验证来源；旧Midscene视觉配方不自动转为Portal已验证流程 |
| PlanRevision | 清单版本、逐项做/跳过、顺序次数、成本是否实测、预算、停止条件、execution_allowed |
| VerificationResult | 任务回执与计数证据、余额证据、是否有冲突、未归因净增；不得以模型verdict覆盖可见配额矛盾 |

拟议配置层：观察字段reader（portal/vision/ocr）、动作backend（portal/显式诊断通道）、页面前后条件、业务要求与成功合同、模型预算、暂停点。新平台主要补配置；新交互需要扩展通用原语，不能承诺任何App只改字符串即支持。

看板复用run/model_call/gain_event，分别展示整轮总耗时、模型calls/tokens、Portal读取/动作耗时、任务结果、实际资产净增、字段未知率、人工补救和支持覆盖。模型费未知留空；积分名义价值与实际抵扣分列。协议成功率不能当业务成功率。

## 9. 成本与范围

以Portal覆盖的部分替代模型读取和定位，减少的是需要模型回答的问题数量；不保证全流程免模型。Midscene仍用现有codex/gpt-6.1-terra，Android规划缓存不包含Web XPath定位缓存，查询不缓存，成本按真实调用计量。

预算建议，均为目标而非实测：

- 成熟任务目标0次，必要时1次合并视觉请求；成熟批次总计最多3次。超出就停并列待学习，不静默追加。
- 首轮学习单任务至多8次模型请求、5分钟总预算，单请求有独立超时；常规流程不自动每天重学。
- 跨调用重试计入总预算，异常收尾也计量；批次计时包括清单、入口、业务等待、收尾，不通过把阶段移出计量“优化”数据。
- 订阅内边际现金支出与按量API备用分别列；当前未核实供应商价格，不编人民币节省额。本地Portal无逐次模型费，仍有设备/维护成本。

初期能力目标：直接领取、经验证的普通浏览、档位领奖。搜索、答题、联动、邀请、组件、游戏保留各自未验范围。只采集了首屏，不将今天列表当后续可直接执行计划。

## 10. 实施计划与验收

1. **整理已测能力并做离线最小适配。**统一Portal连接、快照、字段解析、动作结果；用现有真实旧树/新图冲突与滚轮数字样本验证会拒绝误读。只写必要测试，覆盖真实风险。
2. **完整清单与业务计划。**Portal滚动采集，逐屏落证据、去重、完整性、回顶及真实行绑定；未知项合并评估。验收为完整列表＋明确做/跳过与顺序次数，不以首屏8行代替。
3. **最小正常入口闭环。**自行选择实际合格普通任务，Portal执行、必要Midscene读取、完成验证、结算与下一计划；无手工taskName/补点。局部诊断后尽快回此主线，不长期围绕单配方晋升。
4. **视觉定位到Portal对照。**用已标注截图检查坐标转换，再只做可逆入口操作，确认模型定位与Portal手势互通；出现变化/不确定派发时不重复点击。
5. **按数据决定深适配。**若频繁需要aiAct复杂探索，再评估AbstractInterface设备适配成本；否则停留组合调用，避免提前写完整驱动。
6. **监督复用观察。**跨至少3天累计20个有效机会，目标至少19次无人工补救、错误记账0；公布分类型结果、跳过与人工时间。这是建议初期验收窗，不是稳定性承诺。之后才由用户决定调度。

本轮交付为组合方案；Portal服务安装与少量入口实测已完成，但正式runner适配、完整收集、业务规划和混合执行验收均未完成。先备份再改代码，保持现有入口可回退。
