## 已证实的停止机制及输入证据边界

1. 本地脚本给出目标按钮 tap，engine 消耗源图动作权限。`device.act` 校验当前图及前台后构造 `adb shell input tap x y`，await命令，再检查 stdout 是否匹配错误字符串。
2. `learned_entry_dispatched` 只在上述 await正常返回后置 `dispatched=true` 并保存。因此三次不是“还没到点击环节”，也没有保存的 `act-not-sent` 证明。其 open_task.actions 最终 `status=observed` 的意思是结果尚未确认，不能解释成输入未发出。
3. engine取得第一张新图，明确等待1000ms，再取得第二张新图，然后执行check。
4. 第二图仍是panel。`recoveryAuthority` 明确要求 `!readPanel(f,...).isPanel`，`recoverTask` 因此前置返回null，**不会调用 describe 模型**；check把null映射成上面的通用恢复错误并返回blocked，engine停止。全部三个失败都没有点击后 open_task 的 agent_result。
5. 随后 return_list 在一次新读取确认列表即结束；没有为这三次再发 back 或重复 tap。最后恢复图约+4秒仍列表，但其模型读取完成时间更晚不意味着截到了更晚画面。

归档源而非今天的可变源码：234/235 的 [runtime recoveryAuthority](../data/stage-records/script-sources/3ddfe82d369ba3b9be20b40dfcd3c62ff021aff53d7003ce711815889fca634a.ts#L406)、[null错误映射](../data/stage-records/script-sources/3ddfe82d369ba3b9be20b40dfcd3c62ff021aff53d7003ce711815889fca634a.ts#L853)、237的 [recoveryAuthority](../data/stage-records/script-sources/817d460342395b9a5018845167903ae8510d1a4294565c75747078042e29ec32.ts#L412)、[device input调用](../data/stage-records/script-sources/6fda9fc9cf854f05476ebf1bd8bbd69f48da11d406b1fde5f43fd3cfd6743fdd.ts#L330)、[命令返回判断](../data/stage-records/script-sources/6fda9fc9cf854f05476ebf1bd8bbd69f48da11d406b1fde5f43fd3cfd6743fdd.ts#L389)、[engine blocked处理](../data/stage-records/script-sources/20aa53aa13ccba2cbce99ede053518b7aed0a617c94e0d40471d276ae0f4f1ad.ts#L86)。来源摘要见各运行 source-snapshot.json，相关归档文件内容SHA已核对。

**限制：没有逐次 input命令的原始stdout/stderr/开始结束记录。** 这四个目录的 device-command-evidence 保存的命令全是 foreground：前三次各39份，239为37份。input使用直接adb helper，stdout只在内存判断；默认exec返回路径未把该次stderr落盘。已知的是程序走到正常返回之后，未知的是触摸事件是否进入了指定应用处理器。不能伪造原始命令回执或把日志事件提升成UI已接收证明。

## 对成功率的含义与最小下一步

这三个样本损失发生在**任务入口到达**，还没有进入滚动或浏览计时，不能归责于浏览动作、完成关键词或收益结算校验。继续放宽回执关键词，或增加静态校验清单，都不会解释此处的无可见跳转。已经找到的程序行为是“列表页没有进一步被动观察的恢复路径”，但目前不能把它当成淘宝不跳转的根因，更不能声称改掉就一定提高成功率。

在另外已经授权的**11月3日新一天单任务试验**中，先依据当天实际清单重新选择可做任务；旧批次尝试不清零、不重放。只派发一次当前任务点击。若正常第二次截图仍列表，建议只增加**一次只读观测**：约5秒后保存新截图及已有foreground原文，期间不再tap、back、启动或切换输入后端。这个5秒是一次诊断采样点，不是要加入生产的成功阈值或无限重试。

晚图出现目的页支持延迟假设；出现明确错误就按实际错误诊断；晚图仍列表只能把窗口内未到达的证据拉长，不能把输入丢失或坏链接升格为结论。如果现有终端回执能保留input原始结果，可一并保存；本次不为它修改代码、不唤醒手机、不追加模型调用。
