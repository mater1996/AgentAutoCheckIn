## 新流程的阶段

应用层：设备准备 → 打开并确认目标App → 到达已知应用起点。

活动层：进入目标活动 → 打开并确认活动任务列表 → 收全列表并保存规划。

任务层：从当前列表动态匹配允许任务 → 打开目的页并确认实际要求 → 执行一轮 → 留存当次完成回执。

收尾：返回并确认活动任务列表 → 核验本次任务状态及稳定余额 → 记账和更新计划 → Agent复盘 → 按本批约定暂停并息屏。

活动主页与任务列表面板需明确区分。当前阶段是程序的执行意图，实际页面是观察得到的事实，两者必须分别保存。例如阶段是“返回列表”，实际仍在“商品页挽留弹窗”，不能一发back就把状态改成已回列表。

每一阶段统一配置：进入条件、阶段目标、允许动作、脚本版本及适用条件、完成证据、下一阶段、失败时交给Agent的上下文、时间/请求/动作上限。各活动以配置和可复用动作组合，不写平台标题特判。

## Agent必须接收到的上下文

- 本次sessionId、阶段attemptId、关联的taskAttemptId、应用/活动/账号及设备用户空间；无任务阶段允许taskAttemptId为空。
- 当前阶段及目标、已验证的上一检查点、期望下一检查点；与当前真实页面身份分开。
- 当前原图的frameId、采集时间、实际尺寸与OCR；必要时提供此前关键帧，不能只发错误字符串。
- 当前任务快照、实际要求、计划允许范围和剩余执行次数；当前余额与回执证据的来源和可信状态。
- 正在运行的阶段脚本版本、最近动作、动作依据、结果、错误，以及尚未确认是否生效的动作。
- 已用时间/模型调用/动作预算、可用的动作工具、禁止操作与停止条件。
- 与当前阶段适用条件相符的经验，以及来源版本；不能把整份聊天历史当唯一上下文。

## Agent何时接手、如何交回

1. 阶段首次遇到或没有已验证适用脚本：进入学习模式。Agent看现场，建议一个动作及预期结果，统一执行器执行后保存新图并核验，逐步完成阶段。
2. 已有脚本且前提满足：直接运行脚本。本地检查负责发现按钮缺失、未知页面、文字歧义、配额/要求变化、动作无效果等情况，不必等抛异常。
3. 发生异常：暂停当前脚本，携带完整阶段上下文交给Agent。Agent可等待、读图、建议受限点击/滑动/返回或停止。设备断连等传输故障先由程序处理，不靠视觉猜测。
4. Agent一旦恢复到某个已知阶段的进入条件，就由程序验证该条件，并从指定检查点交回脚本；不重放整个阶段，也不重复尚未确认生效的动作。失败事实保留，即使后来恢复也记录“恢复后完成”。
5. Agent与脚本共享同一动作入口和设备锁，Agent不持有第二套独立手机控制器。模型建议包含frameId、动作目标、坐标或文字定位、执行理由和预期可观察结果；坐标须对应当前帧，画面变化或等待过久后重新定位。
6. 轮次、时间或成本到上限，或遇登录/验证码/不允许操作：保留现场，执行有限安全清理并停止。

顺序、可用总次数、标注奖励变化可触发当前任务快照/局部决策更新，不作为永久能力失败，也不通过不断手改预期次数追逐页面。模型用真实说明和现有计划判断是否仍允许做；已完成次数不因换位置而清零，新任务不继承旧任务状态。列表常规执行按当前顺序选择第一个满足计划与已验证适用条件的任务，只有业务依赖要求时才保证顺序。

## 完成后也让Agent介入

完成某阶段后输出标准化结果，携带关键帧、实际步骤、回执、失败/恢复与脚本版本交给Agent复盘。已有阶段且没有变化时，复盘可用阶段日志和证据索引；需要确认视觉事实时读取关联原图，不需要重新操作手机。复盘成本单列，不宣称整个常规流程完全零AI。

Agent总结阶段经验、标记改进建议并提出候选脚本/配置版本。新版本先做离线检查，再独立复验；未验证版本不能覆盖已验证版本或自动晋升。首次阶段学习结果和异常恢复结果同样归档。阶段完成复盘不等于整项任务已经到账；任务完成后还需跨阶段汇总核验和本次计划更新。

知识归应用/活动/阶段/任务定义，保留来源执行。账号拥有本次页面观测、次数、计划、执行、余额、收益；执行分别记录“实际使用的经验”和“后来从本次提炼的经验”。应用起点/打开App经验归应用，活动入口与返回列表经验归活动，任务做法归任务或经验证的通用流程。恢复经验归发生的阶段及页面条件，不一律塞入任务经验。

## 复用与迁移范围

复用TS/SQLite、账号配置、动作与截图/OCR、设备锁、回执/净收益核验、已有原始证据及v2档案。将Midscene调用点替换为可读图Agent接口和统一阶段执行器；不能只卸载包后沿用旧调用。先接上应用准备、活动入口/列表确认、任务、返回、结算各阶段，再跑完整入口验收。

阶段标准化记录和Agent完成后复盘需要新增接线；不是改一个模型配置就自动具备。此次仅定义方案，未选择新的SDK或修改现有模型凭据；Agent运行时选型须复用已验证读图通道并核实实际图像输入、用量、取消/超时和工具协议能力。

## 验收

离线：验证各阶段进入/完成判定、异常上下文完整性、单一动作所有者、无效果与未知动作的处理、从检查点续跑、动态任务匹配/去重/额度、预算停止、Agent复盘与候选版本不自动晋升。重放已有真实截图与动作日志，离线替身结果不冒充真机成功。

真机：经用户授权的一项普通浏览任务，从当前真实状态开始，覆盖打开App/进入活动/列表匹配/任务执行/取回执/返回/核验/记账/复盘归档/息屏。记录实际起点；已在列表不能声称测过启动与活动入口，另用明确的受限试验覆盖。无父Agent手发open/read/back命令，程序必须自行调用读图Agent并交回。真实未发生的异常只能标未覆盖，不制造风险弹窗以凑验收。
