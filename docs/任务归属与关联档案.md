## 具体关系

应用taobao（com.taobao.taobao）→账号tb_main（user0）→活动tb_coin（资产taobao_coins）。

- tasks：任务实例ID，名称、实际说明、所属应用/账号/活动。上游未暴露稳定任务ID，providerTaskId=null；使用采集来源和原条目形成实例ID，不假装任务名是平台永久ID。semanticKey用于同范围内比较名称/说明，不能仅凭该值自动归并跨批次任务。
- inventories：采集批次，明确完整或局部，关联任务快照ID与证据来源。
- snapshots：当次任务次数、说明、来源帧；任务实体与可变次数分开。位置不具备长期执行权，positionAuthority=false。
- plans：关联完整采集批次；逐项决策通过taskSnapshotId指向当时快照，保留原因/步骤/顺序/限额和旧序号。
- executions：关联实际执行前的目标快照，以及原planId、decisionTaskSnapshotId；保存runId、结果、动作、证据目录、资产ID。历史归属为迁移时回溯匹配，不声明当时程序已消费这份规划。
- experiences：关联来源execution ID、适用任务实例、script ID；保留实际做法、异常和复用条件，状态仍为supervised_only。
- scripts：脚本ID、应用/账号/活动范围、路径和文件SHA256；状态interactive_probe，不能升格为自主配方。脚本修改后校验会提示版本变化，需归档新版本，不覆盖旧验证。
- progress：关联计划ID与已执行ID；标requiresInventoryRefresh=true，已变化的任务没有自动继承完成状态。

每个上述记录在自身scope字段显式保存appId、accountId、activityId，单独拿出也能知道归属。不同范围相同标题生成不同ID。ID为不截断SHA256，顺序/金额等不靠心算，均由程序生成和核验。

## 校验及迁移命令

在项目根目录：

```bash
./node_modules/.bin/tsx tools/migrate-task-records.ts
./node_modules/.bin/tsx tools/validate-task-records.ts
./node_modules/.bin/tsx --test tests/task-records.test.ts
```

迁移先完成内存关联校验及冲突预检，再写入；同一来源重跑内容一致则不重写，已有目标内容不同直接拒绝，不覆盖。各文件采用临时文件后rename，目录整体并非单一数据库事务，中断后可同源重跑补齐。备份原件/哈希清单位于.backups/task-records-ownership-v1/。

校验器拒绝跨活动/账号归属、重复ID、断开的任务/经验/脚本引用、计划与执行任务不同、错误资产、档案与SQLite或脚本版本不符。归属与关系模块不驱动手机，不会把“监督成功”提升为“自动验证通过”。

验证结果：9项新增关联用例通过；根tests/*.test.ts全量340/340通过；本次4个TS文件定向tsc通过。实档校验确认21项、run128/129、2份经验与账本一致；迁移重复运行通过。
