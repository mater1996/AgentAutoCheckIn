# 统一执行目录实施与验收

用户明确要求一次完整活动执行一个独立工作目录，截图、日志和Agent日志统一归档；下一次执行另建目录，并对具体方案回复“执行吧”。此处记录该已批准目录修复，不重置业务批次或旧attempt。

## 已实现

- execution-workspace.ts统一创建root、manifest、runner.log、events.jsonl、plans和summary。所有子任务在root/tasks/<attemptId>，任务索引和文件清单由manifest追踪。
- round-cli正常调用生成新执行ID和新root；仅显式--resume-execution引用先前root。历史已消费、reserved、pending全部继承到同batch；未知输入/未决reservation不会因新目录获得重放权限。
- stdout/stderr在执行中同步写入runner.log；Agent规划输入/输出和plan revisions存于本轮plans，子任务原图请求、模型响应、阶段及动作日志由适配器统一写入任务目录/整轮events。
- 本轮summary只统计result.roundId等于当前执行ID的任务，不把跨执行继承的旧收益重新计入。
- 单任务设备观察/动作实例与runtime使用一致子目录，整轮外层保持一次prepare、同一个锁、最终HOME/cleanup；具体截图路径回归正在实施。
