## 独立 OCR 与促销 500 的边界

六张真实输入（207 failed/next、208 retry、209 full/return、历史50）每张三次独立调用；每次包括完整 scratch PNG 与 shell/badge1x/badge3x/back/coin/promotion 原像素 crop。共18次调用、126个 page 观测；raw、engine/revision、confidence、原始/映射 bounds 和 crop hash 均留档。mapped 公式为 `original=crop/scale+origin`，没有 clamp，没有择优投票或把 crop 注入生产 frame。

- 全页与 badge1x/3x 三次均读出浏览/得50。run209 1x 得50映射 left≈938，较期望930偏差约8，仍在原门槛内；3x left≈936.212。原全页最准确，故不存在“必须新 OCR 才有得50”的证据。
- shell 三次 run209 都是“查看详情”，208 都是“加入购物车”；返回/coin 多数 OCR 空文字，仍靠原图控制谓词。
- run209 全页三次均“下单得500円”，promo crop 却三次“下单得500m”；return-video crop 为“下单得500/”。历史50全页也是“下单得500m”，207/208全页通常“下单得500”。这显示同一视觉促销末端金币图标会被 OCR 当字符，不支持增加任何 `円/m/~/` alias。

**它是否本应按原规则拒绝？必须区分两条已存在的规则。** 普通 `inspectImmersiveBrowse:174–184` 只统计 `/^得\d+$/` 与 `已得`，风险词含“当前页下单／再得500金币”，不含“下单得500円”。因此 run209 真正首拒因不是金额歧义。新 quality `immersive-ocr-quality.ts:73–75` 更严格，只有精确 `下单(再)?得500` 可作为混合得数文本例外；`下单得500円` 会拒绝。quality 还要求原 bounds error（38行），run209 在该前提就不适用。不得为了统一结果改写原 frame 或强走 quality。

现有普通金额权来自固定 badge 内、唯一、几何正确、原像素完整的 **得50**；促销行在 `[888.240,1401.557,1048.792,1434.489)`，与 badge `[878,1230,1060,1376)` 不相交，独立 OCR 和原图都显示是下单推广。绝不从该行提取“500”作为 requirement/receipt。历史 order-only 真负例 `53d057a1-91cc-41e8-975e-dbeacf7b908a` 只有“当前页下单／再得500金币”，原 checker、绕过 shell、新增 shell 三条路径均在174拒绝。

若评审要求所有混合 `得\d` 的未知后缀必须在任何通道统一 fail closed，则 **run209 应继续拒绝**：只增 shell 不足以满足该更严格策略。不要将目前普通/quality 行为差异藏在 alias 中。可以另立版本研究“经原像素完整验证的固定 browse badge 给金额权，其他区域促销只做上下文”的显式分类；本报告没有实现或验证通用促销分类，不能据此拓宽 quality 许可。
