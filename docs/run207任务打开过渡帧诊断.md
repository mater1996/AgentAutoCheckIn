## 停止发生在哪一层

engine.ts:72–82 只在 pending tap 后做一次 ≤1000ms settling。随后 check 得到 blocked，engine:89–98 先把 tap 标 observed 并清 pending，然后立即停止，既不会 script fallback，也不会再次 observe。

runtime.ts:383–385 要求 boundEntry、非 panel、新 frame，再调用 inspectLearned；immersive-browse.ts:155–161 对 observationError/空 OCR 直接 null。runtime.ts:397 对匹配沉浸任务统一 blocked，禁止 continuous/model fallback。这条 fail-closed 的完成规则应保留；缺少的是已成功 dispatch 后对明确观察故障的一次有限重采样。

session.ts:25–27 捕获 open_task 停止后执行 return_list，所以后帧出现在返回阶段，而不是打开阶段。return 的 proposal reason 里“after captured task receipt”是通用文案，本次无 receipt，不能把这句当事实。

## 最小 TDD 恢复方案（待实现）

第一条 tracer bullet 仅覆盖 **已确认 dispatch 的 open_task + 明确 OCR 观察错误 → 一次新的只读采样 → 用原合同重新核验**。不要把任意 inspector=null 都改成可继续浏览；不扩大到 task_receipt，不恢复未知 dispatch，不重开同一任务。

建议最小落点是 runtime 的 open_task 检查分支前增加一个有状态的、单次只读观察 helper。它在同一次 check 内拿 fresh frame，成功只允许返回 destination checkpoint，失败仍返回 blocked；不得基于 helper 的新帧再走普通 proposal/script 分支。这样不必改通用 engine 的 pending/tap 状态机。新帧必须以独立事件持久化并明确参与 destination_confirmed；不能只在局部替换 frame 而遗漏证据。

helper 的全部前提：

1. selected 身份、ctx.taskAttemptId 与 entry 相同；entry.dispatched===true；本次 tap 正常返回且未出现 dispatch_unknown/pendingAction.status=unknown；sourceFrame 与故障 frame id 不同。
2. frame 的 package/user 明确等于 owner，且是支持的局部 OCR capture failure。owner 未知或错误、Foreground changed、登录/验证码/授权/遮挡证据立即停。OCR 失败不能证明页面安全：只允许无 UI 交互的等待/截图，不能赋予任务执行或完成权限。
3. entry 级 retryUsed 在等待/采样前消耗，跨 stage 重入不得复位；最多额外 1 次，建议 wait 上限 800ms 后 fresh capture。等待或 capture 超时/失败即停，不重发 tap，不做 swipe/back/领取/购买/模型恢复。
4. 用本次 check 的剩余时间和 abort signal 限制 helper；deadline 涵盖 wait + capture + inspector，不能 Promise 超时后又继续采样/派生动作。不得重置 stage 90s、session 600s、actions/rounds 原限制。新增 800ms 和已有 tap settling 1000ms 统一计入本 attempt 的观察等待账，与后续 dwell 共用现有 20000ms 上限；重入不重置。真实 OCR/采样耗时消耗 wall deadline，不能充作收益或显式 dwell。
5. fresh frame 必须有新 id、非未来且不过期；owner 再核、panel/blocked 再核、原 v2 检查照旧。唯一 browsing50 才允许 open_task 完成并锁定 50，receipt 保持空；若未知/错误/歧义，直接 blocked。下一阶段从自己的新截图开始，不能沿用故障帧或 helper 帧发动作。

若 helper 的新帧需要返回普通动作而不是仅终止/确认 checkpoint，就应显式调整 engine 的重观察接口，不能悄悄让旧 context 拥有新帧权限；本次最小方案不需要这项扩展。

依次落地的测试切片：

1. **当前独立 RED 已建立**：历史 select→source→panel→OCR failed→normal video 队列，必须消费 normal frame 后才作最终停止/确认。当前实际在第四次 capture 后停止，normal frame 未消费，断言 exit=1；先修这个行为，再要求 destination checkpoint 成功，tap=1、模型=0、receipt=null。
2. GREEN 只加入上述 helper 与预算/事件记录；原始失败 frame 仍被 inspector 拒绝，正常 frame 按原合同通过，不改 OCR/像素合同。
3. 再逐个增加负例：dispatch unknown、owner 错/未知、不同 attempt、未 dispatch、未点击却看到视频、fresh id 重用、过期、第二帧仍 OCR 错、正常 OCR 但未知页、登录/验证码、预算不足、wait/capture 异常、abort 后无后续采样、重入不再重试。断言所有情况无第二 tap/无回执/无模型或 continuous fallback；正常未知页不触发本 OCR 恢复。
4. 增加 shared-budget 边界：已有 1000ms tap settling + 新 800ms 后，剩余 dwell 不超过 18200ms；总 slice/round/action/time 限制保持有效，耗尽只能停止。收益仍须当前 attempt 的真实完成 quote、后续 quota 与稳定余额联合核验。run207 不包含真实 completed50，不能用本浏览帧制造这一正例。
