# 面板文字检查实现

已实现离线任务面板身份策略 `panel-text-v4`。只修改 `runner/staged/activity-navigation.ts`，新增独立测试 `tests/staged-panel-text-policy.test.ts` 与本文；余额、observations、runtime、script-validation 和旧测试均不在本次修改范围。未操作设备、ADB、模型、真实数据库或 cron。

## 规则与边界

- 保留 owner（指定淘宝 package、合法显式 userId、frame 同 owner）、1080×2400、frame id/path/capturedAt、无 observationError 和全部 OCR 合法 bounds 的入口约束。帧新鲜度与消费权限仍由 runtime/device 管理，离线 checker 不用当前时间否决历史 frame。
- 当前同路径 `.ocr.json` 必须是单页 Apple Vision、绑定当前 PNG path、尺寸正确、全部行 bounds 合法。frame 与 raw 各自必须通过风险和布局检查。双方行数、顺序及非任务文字保持一致；同一任务标题允许细化名称，但额度相同、左/上/下边变化≤15px，同文字各边变化≤15px。这是列表身份兼容规则，不替代既有标题 crop 的审计权威。
- 唯一“赚金币抵钱”位于 `[380,465,705,550]`，宽度至少260px；NFKC/去空白后的重复、冲突“领淘金币”均拒绝。
- 有奖励区时，“今日累计奖励”与“完成进度 n/m”必须各唯一且成对，分别在 `[35,600,330,680]`、`[35,680,330,750]`；整数额度须合法且 n≤m。不能把同时缺失的未滚动顶部当作合法滚动页。
- 无奖励区时，首个完整任务标题须在 y≤760，列表仍可读。任务标题解析当前文字末尾 `(n/m)`，不绑定任何任务名称。至少两行完整可读；标题在 x210..820、y575..2285（有奖励区时 y≥770），相邻行顶缘差150..240px，合法额度，行高≥25px。完整可见行都须具备标题下方说明及右侧唯一可读按钮；y≥2160 的底部裁切行允许不完整，但不计入至少两行。按钮仅使用真实 frame 已有通用界面词“去完成／去逛逛／逛一逛／已完成／领取奖励”，不授权点击或任务执行。
- 规范化后的风险词在 frame/raw 两侧检查，包含跨 OCR 行拆开的登录、验证、授权等；独立“广告”“关闭”亦拒绝。没有把“支付宝”任务名当作支付弹窗。
- 只读取当前 PNG 进行格式、尺寸、解码和 SHA 校验，不读取或比较历史 panel PNG/JSON。`activityPanelSource.files` 保留旧 SHA 和来源作为历史 provenance，`policy` 明示它们不再授权像素。home/landing 分支保持原样。

位置范围来自真实195/203顶部、209滚动和其他原 frame，不以固定任务名推测业务。仍是当前1080×2400布局策略，未知布局返回 null，需要抛给用户。

**文字策略不能证明图标完整或阻挡静默覆盖。** 测试刻意将当前 PNG 改为白图，同时保留同路径文字记录，预期接受；这准确表示用户批准的新政策，不声称仍能拒绝 stale OCR 的纯像素覆盖。旧 panel 遮挡测试恰好因临时 PNG 未携带同路径 raw OCR 而拒绝，不能拿它当新政策防遮挡证据。
