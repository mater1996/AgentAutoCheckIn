# 派发前前台读取恢复

本次实现仅适用于 `navigationPolicy=current-text-v1` 下 `enter_activity`、`open_list` 的正常导航 tap。离线验证已完成；是否在真实手机触发并成功，交由父任务验收。没有执行手机命令、模型请求或账本操作。

原问题：设备先消费 frame，再读取 foreground。若 dumpsys 成功退出但同时缺失 `topResumedActivity` 和 `mResumedActivity`，input 尚未发送，原运行时仍把它归为 unknown 后停止。

现在的行为：

1. `AdbOcrDevice.act` 只在私有 `MissingForegroundMarkers` 且原 foreground 证据成功落盘时，生成 `act-not-sent-v1`。它包含已消费 frame、原 action、`inputSent:false` 和原命令完整输出的 SHA 引用。设备用私有 `#unsentActs` WeakMap 绑定同一 error/action/frame 实例；调用者不能通过错误文案或字段伪造，凭据只能领取一次。
2. runtime 只为上述两阶段领取凭据。恢复额度每 session 共一次，在进程 Set 和既有 runtime.jsonl 中查重；改变 taskAttemptId、阶段、重建 runtime 都不会重新获得额度。resume 不恢复。
3. 恢复只调用一次 `device.capture()`，保留完整 PNG、raw OCR、frame JSON 和两次前台核验。绕过 observe 的读取重试和模型 reader，用真实 `inspectCurrentActivityNavigation` 独立确认同一 home/landing 类型、相同版本及唯一原目标，再从新 frame 的当前 bounds 生成 tap。
4. engine 新增可选 `recoverUnsentDispatch`，原 dispatch 抛错后最多调用一次。它沿用原 deadline 和预算，验证新 frame 未消费、proposal 合法、动作类型与 expected 不变；更新同一个 ActionRecord，保存 `dispatch_not_sent_revalidated` 的原 proposal、新 frame/proposal 和证明。第二次 dispatch 位于恢复 catch 之外，不能再次恢复。
5. 最终 input 前设备再次同步调用 runtime 的原 stage/session guard，避免 foreground 命令晚返回后发送已过期 input。新 frame 保持 15 秒限制和一次消费。真实 input 异常、owner 变化、malformed/ambiguous foreground 都不恢复。
6. runtime 保存 not_sent、consumed、revalidated、sent/unknown、arrival；navigation-records 的原派发状态为 not_sent，实际发送及到达绑定新 frame。独立 `verifyAuditNavigationStages` 从设备证明、命令原文、原/新 PNG 与 raw OCR 重算整链，仍要求每阶段至多一个实际 tap。

修改范围：`runner/staged/device.ts`、`runtime.ts`、`engine.ts`、`contracts.ts`、`script-validation.ts`；新增 `tests/staged-pre-dispatch-foreground-recovery.test.ts`、`staged-unsent-tap-proof.test.ts`、`staged-unsent-dispatch-engine.test.ts`，以及本文。engine 的最小扩展已先向父说明；原 beforeDispatch 无法承接 act 内部消费后才出现的异常，故不在 runtime catch 中暗发第二坐标。
