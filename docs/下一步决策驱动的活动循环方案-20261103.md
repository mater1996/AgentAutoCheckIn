# 当前状态驱动的下一步执行方案

2026-11-03。状态：方案，待确认；未修改生产代码、未操作手机。用户最新方向替代此前“每回列表完整采集再全局规划”的设计目标。

## 用户目标的重述

程序和AI承担同一种决策职责：根据当前真实页面、执行目标、已做记录和已学流程，确定下一步。代码有可靠的当前依据就由代码继续；代码无法判断时让AI补决策，不为调用AI额外建设一条全量识别主线。

任务列表上的一次AI决策应同时给出当前状态、下一项可执行任务、当前可执行动作，以及该任务的可更新执行计划。无需先整理整张或全部任务清单，再调用一次模型从中选择。进入任务后沿用同一观察→决定→执行→核验循环。返回列表时重新观察位置，但保留业务记录。

## 之前与建议改成什么

之前：每项任务后完整从顶扫到底→读所有字段和位置→模型规划全部任务→回顶找目标→再次定位→执行一项。

建议：回到列表→观察当前页面→复用流程或AI选择当前从上到下第一项符合范围且未消费的任务，同时定位按钮并给计划→执行→核验记录→返回列表继续。有候选即执行，不为列全后面的任务继续扫描。当前屏没有合格候选才滑到下一屏。

顺序默认从列表顶部开始按屏向下找；返回后列表可能变动，应重新确认顶部并重新查找第一合格项，不继承旧坐标。实际边界和滑动过程可以代码判定，无法判定交AI。扫描属于查找动作，不要求枚举保存每一项任务。

## 统一循环

1. 新建一次活动执行目录，加载账号/活动目标、范围禁令、跳过、尝试历史、可用动作和已学流程。
2. 打开应用、活动、任务列表。每步先判断已学脚本能否基于当前证据执行；不确定时AI返回下一步。
3. 列表页：确认当前列表状态；找到第一合格任务时返回任务身份、实际要求、当前次数、所需基线余额、按钮目标、计划与当前一步。不要求其他行的位置。没有候选则返回下一屏查找或准备结束的理由。
4. 派发前持久化本次任务及动作意图。代码执行受支持动作，截图/日志/模型请求响应自动归档。历史坐标不能跨返回复用；复用的是如何识别和执行的规则。
5. 任务内：按当前计划执行可确定步骤；遇变化时AI更新计划、阶段和下一步。计划中的未来步骤是条件描述，不是提前猜好的一串坐标。可以一次决定并执行已确认要求的有限动作段，例如连续滑动，不能插慢模型调用打断实际浏览要求。
6. 完成判定：记录明确任务回执，返回正确列表/资产页并用两张新帧核实余额；分别记录任务收益、额外签到和无法归因变化。缺回执不凭余额差报成功。
7. 更新该任务尝试状态、次数和计划，返回列表后新观察、新选择。已消费失败/未知不在本批重试；输入结果不明、登录验证码等按既有规则停止。
8. 完整经过当前列表从顶到底且没有允许的未消费候选，才判定本轮无剩余可执行项。不能因当前屏无候选或模型一句“没有”就退出。结束前的这次覆盖扫描可以只逐屏判断是否有候选，不必生成全量任务表。动态列表可能在扫描之后继续刷新；“无剩余”指本轮已观察列表状态，不宣称未来任务永久不存在。
9. 保存汇总，返回系统桌面、息屏并验证。若真实安全门槛停止，仅执行已允许的安全清理，不假称正常完成。

## AI上下文与输出契约

输入：当前原图/尺寸/frameId，目标应用/账号/活动/资产，当前阶段，选中任务与原要求，当前attempt，已做/跳过/未决记录，最近动作及结果，已学流程/可用动作，业务禁令。模型不能靠任务名或宣传词代替真实要求判断。

建议输出字段（示意，不是新模型结果）：

```json
{
  "frameId": "current-frame-id",
  "state": {
    "page": "task-list",
    "phase": "select-next-task",
    "listPosition": "top",
    "balance": 2845,
    "blocked": false
  },
  "decision": "execute-task",
  "reason": "当前可见第一项允许且本批未尝试的任务",
  "task": {
    "name": "逐字任务名称",
    "instruction": "逐字真实要求",
    "done": 0,
    "total": 1
  },
  "plan": {
    "goal": "完成该项允许任务并核实所得",
    "attemptsAllowedNow": 1,
    "steps": [
      {"when": "任务行确认", "do": "打开对应任务"},
      {"when": "进入任务", "do": "核实当前要求并执行支持的流程"},
      {"when": "看到明确完成回执", "do": "保存回执、返回所属列表并核账"}
    ],
    "stopConditions": ["登录或验证", "要求超出授权", "输入结果未知"]
  },
  "nextAction": {
    "type": "tap",
    "target": {"label": "去完成", "bounds": "当前截图实测按钮框", "point": "当前截图实测点击点"}
  }
}
```

上面target用占位文字说明，正式schema使用实际数值。不同decision使用不同结构：execute-task、continue-task、scroll-list、return-list、finish、stop；不是每次都填task/plan/point。没有数据用null/明确unknown，不制造字段。动态规划脚本为现有执行器可消费的受支持动作/条件DSL，不是任意AI生成JS在机器上直接运行。AI只返回下一步可执行动作；不确定的后续步骤保持条件分支，执行后再观察。

## 校验的边界

本次动作才检查本次目标的唯一对应关系和坐标；其他行的标题框不参与。做选择需要任务身份/要求/当前次数，做结算需要所属资产余额。AI说完成/可执行本身不构成收益或新权限。输入一次、防重、任务归属、日志归档和真实核账保留，不引入新的人为业务时长/次数上限。

## 实施与验收范围

复用TS/SQLite、统一执行目录、单dispatcher、脚本库、截图/模型接口、连续动作、回执与记账。替换全量collect+全局planner作为每任务前置条件的主线，统一脚本与AI的NextDecision契约；任务记录与屏幕搜索覆盖按需增量更新。

验收先用保存原图和隔离边界验证：选中即执行、不扫描后屏；返回后位置变动不会点击旧位置；新任务替换可选；当前屏无候选只滚动；遍历到底无候选才结束；失败/未知不重试；未选中任务坏框不阻断；连续动作与回执结算保留。再正常入口真机验收，分别报告已执行任务、到账、运行时AI介入、人工介入和卡点。未完成真机循环不得称整轮跑通。
