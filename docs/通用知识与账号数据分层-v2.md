# 通用知识与账号数据分层（v2）

已执行拆分迁移，当前索引：data/task-records-v2/index.json。

## 两层各存什么

通用知识data/task-knowledge/taobao/tb_coin/：应用和活动定义、21份任务定义、2份经验版本、2份脚本版本。scope只有appId/activityId，不绑定accountId。经验包含适用任务定义、实际观察到的步骤/完成提示/复用条件及来源引用；不复制某账号的次数、余额、收益、决策或进度。经验来源sources里保留账号、执行ID、runId及原始结果路径用于查证，这些是来源而非使用范围。

账号数据data/account-task-data/taobao/tb_main/tb_coin/：21个任务实例、采集与快照、规划、执行、进度；保留appId/accountId/activityId。任务实例通过taskDefinitionId指向通用定义。执行和SQLite中的run128/129对应，收益、余额与次数仅存在账号数据/原始账号证据中。

脚本版本保存在通用知识目录script-sources/内，按内容哈希校验并保留原路径。现有probe代码仍有设备/目标假设、仍需人工命令，状态interactive_probe；放在通用层不代表已验证跨账号可直接运行。

## 关联方式

应用→活动→任务定义→经验版本/脚本版本。
账号→任务实例→当次快照→具体计划与执行→收益。
经验版本sources→来源账号和执行；执行derivedExperienceVersionIds→由这次运行提炼出来的经验。

前两次运行usedExperienceVersionId=null，因为当时没有使用后来才生成的经验。今后实际使用经验的运行才填确切版本，不将“提供了学习证据”误写成“调用了该经验”。

同活动、同名称与要求的定义/过程版本ID不包含账号；账号变化不会强迫复制整个知识定义。但同名同要求只是定义身份，不足以证明做法可复用，必须再匹配页面、要求和完成条件。没有平台提供的稳定task ID，因此保留providerTaskId=null，任务定义不伪装为平台永久对象。

经验验证仍为supervised_only、crossAccountValidated=false；没有第二个账号真机测试，本轮只用离线测试验证隔离和共享身份。奖励、具体次数和人群差异继续保存在账号观测中，不并入通用定义。

活动定义沿用现有tb_coin作为当前淘宝活动的标识，数据库原activity仍是账号活动配置；此轮未改SQLite schema。新账号需要绑定同一activityDefinitionId，同时拥有自己的活动配置/状态。现有SQLite应用/账号/活动主键模型的生产多账号改造不在此次档案拆分中完成。
