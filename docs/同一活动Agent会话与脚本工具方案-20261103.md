# 同一活动Agent会话调用脚本工具：与当前分次判断比较

状态：方案讨论，未修改代码或操作手机。

## 建议

一次活动执行对应一个Agent逻辑会话和独立工作目录。Agent在该会话中持续获得目标、规则、当前状态、最近工具结果，选择工具执行下一步；已有TS脚本作为工具能力保留，SQLite是已尝试、收益、reservation的权威存储。程序工具执行器仍承担实际动作派发、输入防重、归属与核账，原始日志落盘。可确定脚本段内部自动执行，不强迫AI逐点击调用。

这与当前行为存在实质区别：当前round程序控制select/open/receipt/return/settle等固定阶段，每一阶段调用独立system+user原图判断，返回JSON由程序按既定分支处理。推荐改为Agent控制业务顺序和分支，工具层控制执行约束与真实结果。脚本返回needs_decision时同一个Agent会话继续处理，不因为阶段更换新建Agent身份或要求本地先判成某类已知浏览才允许模型判断。

## MCP与会话是两个维度

MCP是工具暴露/发现/调用的协议；原生function tools也可承载同样能力。同一会话可以调用MCP，也可以直接调用本机函数；独立请求也可以调用MCP。安装MCP不会自动建立记忆、状态恢复或循环。

最新讨论方向为CLI宿主＋插件：Codex CLI或Claude CLI管理活动Agent会话，插件组合Skill与MCP业务工具，现有TS项目保留为设备、脚本、状态与核账后端。活动执行Agent不修改插件、Skill、脚本或配置；现有工具执行、有限恢复、事实记录与事后优化分开，优化建议交由调用方处理。需要面板发起时再使用非交互CLI或SDK；两种入口共用同一工具后端。若未来选择纯TS嵌入，才优先直接注册函数工具。具体CLI插件加载及模型gateway的协议支持需实施前验证，不能从json_object成功推定tools/tool_choice/图片工具结果支持。协议适配与业务能力分离，不重写已学脚本。

## 建议工具边界（接口示意，不是现成API）

- observe：获取当前原图、前台归属和状态引用。
- list_capabilities/get_recipe：查看脚本能力、适用条件、参数、输入/结果语义；按需取代码，不每轮发送所有源码。
- enter_activity：执行已学APP→活动→列表导航，返回实际检查点或needs_decision。
- execute_recipe：在当前attempt下执行已学任务或返回流程，返回completed_observed/needs_decision/blocked/input_unknown等实际结果、截图与错误，不等同于已记账。
- act：仅脚本未覆盖时执行当前截图绑定的点击、滑动、返回或等待；入口仍统一reservation/attempt，不能通过另一工具重复点击。
- reconcile_task：读取/判读证据后核验所属资产余额、回执和归因，并保存SQLite；不能让Agent直接以“完成”写收益。
- get_run_state：返回持续维护的摘要、历史身份/尝试/跳过/当前任务、已确认收益、证据索引。
- finish_activity：检查结束理由，返回HOME/cleanup/screen-off实际验证结果；阻挡页按原授权停止。

这些是语义能力，工具数量可按既有代码合并。observe可通过工具返回原图；脚本也可直接带出失败时当前原图，避免无意义再次截图。工具输出以事实摘要+证据引用为主，不回灌完整stages/reviews。

## 一轮示例

Agent调用enter_activity→看到列表截图→结合历史选下一项→调用execute_recipe(task,recipe)。脚本完成则给回执/已返回等结果；页面变化则带图返回needs_decision，Agent根据上下文调用act或另一支持脚本。Agent调用reconcile_task记录结果→重新观察列表→继续选下一项。当前屏无任务则滑动；从顶部查找到底且无合格候选才finish_activity。遇实名/登录验证停止并报告，不因Agent自主调度取消既有范围规则。

## 同一session与独立调用的区别

同一session依然是多次模型HTTP请求，不是模型在一个请求中永久运行。客户端保留system/user/assistant tool_call/tool结果这条对话链，后续请求携带相关历史或压缩摘要；provider conversation机制可选但不是必需。

连续会话更易保留当前意图、刚才为什么这么做、脚本失败的上下文，减少阶段拼装造成的信息丢失；但不自动减少tokens，每轮重发越来越长的历史反而会膨胀。需要当前截图+相关最近交互+持久状态摘要，旧图/长日志归档、按需取证。模型记忆不是账本，恢复仍依赖SQLite、pending reservation与动作状态。

独立调用适合范围窄且输入/输出稳定的纯识别、分类等组件，隔离和测试更直接；用于整轮编排则需要程序每次手工重建足够上下文，固定分支增加。可以保留独立视觉读取器作为工具内部能力，但不让其主导业务循环。

## 初始化、活动执行与事后复盘的最终分工

本节根据用户最新纠正替代此前“执行中自动改脚本、更新Skill”的提议。当前仅修订方案，未实施插件或操作手机。

### 角色与修改权限

活动执行Agent负责使用既有工具完成业务、观察新页面、选择下一步、执行已有恢复流程、记录事实与汇报。活动期间不修改插件、Skill、脚本、配置或完成判定规则。工具后端可以正常写本次截图、动作日志、任务状态和核账记录；这些数据写入不等于修改程序。

调用方（用户、主Agent或独立维护流程）在收到报告后，结合原始证据决定是否修改脚本、配置或经验。修复、验证、发布属于后续维护执行，不阻塞本轮处理其他合资格任务。最终汇报是本轮总结，不要求等待源码修改完成。未来若授权自动维护，也应为独立维护任务，不能由签到Agent顺手扩大范围。

### 卡住或失败时怎样继续

执行Agent实时记录失败步骤、截图、最近动作、回执/余额状态及错误，避免结束后凭记忆推断。它必须判断当前下一步，但不在执行中反复撰写经验或修改规则。

1. 很容易处理且仍在原授权内的问题，如普通引导、已知弹窗、页面未加载完，可调用现有观察/动作/恢复工具处理后继续同一次attempt。无需先写代码或Skill。若出现新的业务门槛，不能当普通弹窗处理。
2. 当前任务无法完成但手机输入状态明确，保存失败或未确认结果，通过既有安全返回工具回到列表，跳过该任务，继续其他允许任务。同批次已派发尝试不因失败、重启或新执行目录自动获得重试权限。
3. 普通白屏或导航卡死且已有证据支持，在预先授权的当前应用重启范围内，调用恢复工具杀端重进，重新导航到活动列表；重启记录恢复检查点与全部已尝试状态，不能重新执行失败任务入口。恢复目的为继续其他任务，不是反复尝试领取同一奖励。
4. 恢复也没有页面进展、回不到可信列表或没有新的证据/可用恢复路径时，停止本轮并报告，不无限返回或重启。不设置任意次数/时长cap代替这些语义停止条件。
5. 登录、验证码、人机验证、实名/授权/消费等用户禁止门槛，或动作是否已派发不明、设备归属/锁失效、持久状态无法可信保存时，仍按原约定停止。不能把“尽量绕过任务失败”理解为绕过验证或输入未知后继续操作。

普通任务失败原则上局部隔离，不应让整轮立刻报废；硬停止条件不能被重启应用清除。恢复是否成功须有当前页面证据，发了返回/force-stop命令本身不证明已经回到任务列表。

### 初始化和学习

插件最终只提供 run-activity 与 explore-and-review 两个主要Skill。run-activity负责签到执行与本轮结果汇报；explore-and-review负责初始化探索和事后深度复盘，支持整个活动或指定单个任务/流程。后者区分只读复盘与真机探索：只读复盘不操作手机，探索按调用方明确范围使用现有工具，记录APP→活动→列表入口、实际任务要求、动作、回执与核账证据。已有验证流程先复用，不把历史已学类型重新逐项首学；未出现的任务保留待学习。两个Skill均可输出报告，不设独立report Skill；签到执行不自动切到探索或改插件。

初始化输出为真实探索轨迹、可复用流程候选、任务能力映射及验证缺口，交调用方整理成脚本或配置并验证发布。初始化的目标确实是学习，但“探索并记录”与“直接修改已发布插件”是不同权限。若另行明确授权生成草稿，可输出到本次候选材料中，仍不自动激活为正式脚本。初始化可专门完整扫描任务清单，日常执行仍逐屏选择下一项。

### 结束后给调用方的报告

执行过程中持续保存结构化事实；活动结束或被迫停止后再统一总结。报告包括：

- 业务结果：尝试、确认完成、跳过、失败、未确认、确认收益与未归属余额变化。
- 每条失败流程：任务实际要求、使用脚本版本、从哪个检查点开始、最后明确成功步骤、失败步骤、实际错误/页面证据；原因不清则标未知，不把推测写成根因。
- 恢复记录：执行了哪些返回/重启/重新导航、结果是否核验成功、是否继续了后续任务，失败任务是否保持已消费状态。
- 可优化项：调用方可考虑改哪里、为什么、预期效果、需要怎样验证；与已经证实的经验分别列出。
- 本轮限制：哪些任务受门槛阻挡、哪些收益无法归因、哪些恢复或候选流程尚未验证。

报告及机器可读issues交调用方；不直接覆盖长期Skill。通用流程经验、活动配置与账号数据仍分开。是否采用建议、修改发布及后续独立复验由维护流程决定。

## 风险与验证

改变调度者并不会自动修复点击无跳转、视觉误读、平台实名门槛或网络超时。现有严格门禁若仍在工具内部以不相关字段拒绝，Agent同样无法继续，需要按实际用途整理。工具层保留必要约束，不能把所有检查删除或依赖提示词禁令。

实施验收：先验证现有gateway的原生工具调用/多轮图像返回合同；复用TS工具包装和持久状态，完成单次活动Agent的连续两任务、脚本needs_decision后继续、失败不重试、日志完整、正常结束/真实门槛停止。只证明MCP可列工具不算业务验通。
