# 连续与视频组件优化实现

本次实现仅离线检查器与派发前复核。runtime、config、main、audit、账本和历史原件没有改动；父任务接入 engine→runtime 后才能宣称正常入口集成通过。没有执行 ADB、真实 OCR、模型或 cron。

## API（已冻结供父任务接入）

```ts
inspectCurrentLearnedBrowse(frame, owner, options?)
// options 与 LearnedBrowseOptions 一致：默认 50；显式 20/50；仅 50 支持 requiredMs:25000。
// 返回旧 inspection 兼容的对象或 null，version 为 learned-browse-current-components-v1。

inspectCurrentImmersiveBrowse(frame, owner, requirement?)
// 默认 {rewardCoins:20}；显式支持 20、35、50。
// 返回 ImmersiveBrowseInspection | null，version 为 immersive-browse-current-components-v1。

const policy = {policy:'current-components-v1'} as const;
const selected = await selectContinuousContract(frame, owner, {}, policy);
await inspectSelectedContinuousContract(fresh, owner, selected, policy);
await revalidateBrowseSwipe(old, fresh, proposal, owner,
  {...policy, selectedContract:selected});
```

selectContinuousContract 原有第三参数是 dependencies（测试注入只能拒绝授权），policy 位于第四参数。inspectSelectedContinuousContract 的 policy 位于第四参数。revalidateBrowseSwipe 的 policy/selectedContract 位于第五参数。省略 policy 继续旧像素策略；已选合同记录 owner 与 policy，后续不可切换，不从完成页重选。不存在跨子任务的未冻结共享 helper。

## 行为与边界

当前策略从完整当前文字组件取得要求、金额和状态，校验相对布局与组件可见性；不要求历史商品、价格徽标、促销背景、±4/8 像素位置或整幅画面一致。连续浏览从当前要求下缘生成安全内缩的向上 swipe；视频仅提出 3000ms wait，无购物、关注等动作。

每次读取 .png、相邻 .json、.ocr.json，保存 frame 必须与输入一致；raw 的 engine/languages/revision/file/尺寸、全量文字与几何都要重新校验。raw→saved 仅重现 device.ts 现存 ±0.001 浮点边界规则，不改写原件、不扩大越界范围。组件内部对比度和连续空白条用于发现全遮挡与局部遮挡；这些是当前画面的可见性检查，不是历史像素模板。

连续要求保留现有严格边界：20/50、默认 1–10 秒版本与显式 25 秒/50 版本互斥；错误时长、金额、完整文案、重复/竞争要求拒绝。现有合同的来源 PNG/JSON SHA-256、预算（16 次/18000ms 或 30 次/35000ms）保留。复核要求新 frameId、更晚时间、有效原动作、同 owner、同已选合同，并重新生成坐标。

视频浏览支持真实来源的 20/35/50。完成支持真实来源 20/35；35 保留“浏览”上方与“已得35”下方的实际布局。没有真实 completed50 来源，新策略即使收到“已得50”也返回 null（unknown），不把旧策略的合成 completed50 当作完成证据。20→35 的奖励 transition 不由检查器自行授权；调用方必须使用现有、明确的 transition 合同。

父 runtime 继续负责实际 entry dispatch、任务与 attempt 归属、owner 前台证明、capture age、一次消费、累计 swipe/wait 预算、真正 transition、完成后返回与稳定余额结算。检查器本身不证明当前任务已获收益，不得把浏览或等待时长转成 receipt。

## TDD 与回放

逐轮观察 RED→GREEN：新增连续 API缺失；部分文字遮挡误接收；显式 policy 未选中；复核没有走已选合同；视频 API缺失；视频金额部分遮挡误接收；跨行登录文字误接收；嵌入的竞争奖励误接收；raw 浮点边界与 device 不一致。每轮先运行定向失败测试，再实现并重跑；原有拒绝路径与默认分支保留。

新测试文件含 13 个顶层测试，覆盖 14 个不同真实正例 frame（连续 153/171/187/194、152/192、155 两种商品布局；视频 145/191/172、真实 20/35 完成）。组件移动、去除商品/促销、重复 metadata、遮挡及错误 OCR 是明确标记的 synthetic 回放，不计作独立真实采集或手机验收。合成文件全部位于 scratch，嵌入 raw.file 改为 scratch 目标，原件 PNG/JSON/raw 在每个回放前后核对 SHA-256。

## 局限

当前文字策略信任同帧 OCR 的文字识别结果。保存/raw 一致与对比度不能证明 PNG 上每个汉字确实与 OCR 相同，也不能识别所有没有文字、没有盖住组件的静默遮罩；细小缺笔、同等纹理遮挡可能漏检。未知样式和原始 observationError 继续返回 null，不借用旧像素或放宽 quality sidecar 来兜底。大幅字体/尺寸变化尚无独立真实采集覆盖。未经过手机验收，不提供稳定性或收益承诺。
