# 已学任务稳定脚本验收方案

用户已授权持续推进16项已学成功任务的稳定脚本，不再每项询问；此前明确目标、两类共用脚本及逐项复验构成本次实施依据。仅范围内浏览/已确认领取任务，不扩展游戏、搜索、跨App、邀请、安装、消费、授权；调度保持暂停。

之前：有首次成功、候选代码与归档，但熟悉的5秒浏览/回执仍依赖模型。现在：建立带来源和版本的页面合同与执行配方，普通停留浏览/连续滑动共用执行器；特殊多层店铺和领奖路线保留独立合同，不能靠任务名猜。模型只在不匹配时恢复；纯脚本验收模式遇不匹配即明确失败，不能把模型补救算零模型通过。

先从现有16项成功证据生成完整状态清单，所有未验证项保留candidate。历史原始PNG/OCR用于回归、负例和合同来源，不冒充新验证。当前帧检查页面身份、独立要求、可操作范围、真实完成组件与本次任务入口归属。停留只在匹配条件下有界等待，滑动执行一轮，结束读回执；返回/结算需正确活动与稳定余额，不能按模型思考时间代替脚本等待。

每个版本要至少两次不同session、正常入口、相同脚本hash、无人工补救、任务执行段无模型、真实正收益且归档/清理通过，才能标稳定；登记验证需读真实final/result/stages/usage等证据，而非填声明。通用部件的独立验证与每项任务覆盖分别记录，不因通用流程通过自动宣称16项全通过。不得修改原始执行记录或把失败改成功。

离线先红后绿补真实图回放与真实engine/runtime集成测试，保持旧入口行为；写前备份文件和SQLite（store现有备份）。真机串行持锁，按当前列表动态选择16项中可用且还有次数的任务，每项新attempt、至多两次独立复验，不强行重做日限1/1或消失任务。不扩quota，不追历史内容名字。若所有当前候选均完成/缺席，则把剩余项标为环境阻塞并说明需要后续入口/日期，不能靠循环刷新碰运气。

本批次最后核对账本收益、记录所有失败/模型成本/剩余清单、息屏读回并报告。若实际入口缺席导致16项不能全部完成，交付实现、已验结果及精确阻塞名单，不伪造稳定状态。
