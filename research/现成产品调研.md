## 二、逐个看

### ⭐ 肉包 Roubao —— 2,407 stars，MIT

- 仓库：https://github.com/Turbo1123/roubao
- 定位：**首款无需电脑的开源 AI 手机自动化助手**
- 原生 Android Kotlin，**用 Kotlin 重写了 MobileAgent 框架**
- 权限方案：**Shizuku**（启动一次，之后免电脑）
- VLM 驱动 + 多 Agent 协作 + Skills/Tools 架构

**它的核心卖点**（README 原文）：

> 市面上几乎所有手机自动化开源项目（包括阿里的 MobileAgent）都是 Python 实现，需要：
> 在电脑上运行 Python 脚本、手机通过 USB/WiFi ADB 连接电脑、截图通过 ADB 传输到电脑……
> **肉包完全不同**：截图、分析、执行全部在手机本地完成，无需电脑中转，延迟更低。

**为什么这个重要**：它把「必须有台电脑连着手机」这个约束彻底去掉了。

### ⭐ ApkClaw —— 800 stars，Apache-2.0

- 仓库：https://github.com/apkclaw-team/ApkClaw
- 官网：https://apkclaw.ai/
- 架构：消息通道 → TaskOrchestrator → AgentService → ToolRegistry → 无障碍服务

**最贴合你场景的能力**：
- 支持 **钉钉 / 飞书 / QQ / Discord / Telegram / 微信 ClawBot** 六个通道远程下发指令
- **有定时任务**（ZNDS 测评原文：「ApkClaw 内创建『定时任务』…每天固定时间自动打开红果短剧签到」）
- 不用 root、不用虚拟定位、安卓全机型
- **本地处理操作**，账号信息不上云

**工程细节（值得学的）**：
- Observe → Think → Act → Verify 循环
- **循环检测**：维护 4 轮 `(screenHash, toolCall)` 指纹，全相同就注入系统消息强制换策略
- **Token 优化**：把历史 `get_screen_info` 结果替换成占位符，只保留最新一次
- 遇到系统级受保护弹窗（权限对话框）会截图发给你，中止任务 —— 不硬闯
- 最大 40 轮迭代

**商业版**：apkclaw.ai 有订阅和 credits（Stripe 收款）。

### Andclaw —— 514 stars，MIT

- 仓库：https://github.com/andforce/Andclaw
- 官网：https://andclaw.app/
- **零外部依赖**：纯无障碍服务，无需 Shizuku、无需 ADB、无需电脑
- 支持 Kimi Code / Moonshot / 任意 OpenAI 兼容 API
- 远程：Telegram Bot + 微信 ClawBot（iLink）
- 双模感知：优先 UI 节点树，WebView/浏览器场景自动切截图
- 循环检测 + 截图视觉重试

**它自己做的对比表**（原文）：

| 特性 | Andclaw | Open-AutoGLM | 肉包 | 豆包手机 |
|---|---|---|---|---|
| 无需电脑 | ✅ | ❌ 需 PC 跑 Python | ✅ | ✅ |
| 无需 Shizuku/ADB | ✅ 无障碍 | ❌ | ❌ 依赖 Shizuku | ✅ |
| 远程控制 | ✅ | ❌ | ❌ | ❌ |
| 开源 | ✅ | ✅ | ✅ | ❌ |
| 需专用硬件 | ✅ 不需要 | ✅ | ✅ | ❌ 需 3499 元工程机 |

⚠️ 注意：想用满能力需激活 **Device Owner**，而 Android 限制必须先**恢复出厂设置**。不激活也能用，只是权限受限。

### Hamibot 淘宝签到助手 —— 免费

见上一版文档。免费、2026-10-18、覆盖淘宝 5 个 + 支付宝 6 个签到任务。

## 三、那「签到平台」还缺什么

**这批产品解决的是「怎么让 AI 点手机」，不是「签到管理」。**

| 能力 | 肉包 | ApkClaw | Andclaw | Hamibot | 你要的 |
|---|---|---|---|---|---|
| AI 看屏操作 App | ✅ | ✅ | ✅ | ✅（脚本式） | ✅ |
| 定时任务 | ⚠️ 需确认 | ✅ | ⚠️ 需确认 | ✅ 云端定时 | ✅ |
| 远程下发指令 | ❌ | ✅ 六通道 | ✅ 双通道 | ✅ REST API | 可选 |
| 无需电脑 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 多账号 | ⚠️ 靠系统双开 | ⚠️ | ⚠️ | ✅ 多设备配对 | ✅ |
| **签到模型**（账号/活动/时间窗/状态） | ❌ | ❌ | ❌ | ❌ | ❌ |
| **收益记账**（积分→人民币/三口径/有效期） | ❌ | ❌ | ❌ | ❌ | ❌ |
| **签到面板**（今日状态/收益/连续天数/漏签损失） | ❌ | ❌ | ❌ | ❌ | ❌ |

**所以：执行层不用写了，记账层和签到模型还是空白。**

这也回答了你一直问的「为什么只能我们开发」—— 不是没人做，是**做的人只做到「会点手机」这一层**，没人再往上做「签到资产管理」。因为：
1. 这批项目都是 2025-12 ~ 2026-03 才出现的（豆包手机带动的一波）
2. 做的人目标是「通用手机 AI 助手」，签到只是它众多用例之一
3. 记账是很垂直的需求，只有同时懂签到 + 懂投资/记账的人才想做

## 四、成本问题：你问「直接用远程模型不就好了」

**对，你是对的。我上一版推本地模型是过度设计。**

算一下真实成本：
- 一次签到任务约 15 步，每步输入约 2K tokens（UI 树）+ 输出少量
- 合计约 30K tokens / App / 天
- **DeepSeek / Kimi / GLM 国产 API 约 ¥1~4 / 百万 tokens**
- 8 个 App × 365 天 = 约 88K tokens/天 × 365 ≈ 32M tokens/年
- **年成本约 ¥30~130**

**这个钱完全不用省。** 本地模型的收益是省 ¥100/年，代价是 6GB 磁盘 + 配置折腾 + 推理慢。不划算。

**结论：直接用便宜的国产 API。** 如果哪天想省钱，再切本地 Ollama（都是 OpenAI 兼容接口，改个 base_url 就行）。

## 六、怎么选执行层

| 如果你… | 选 |
|---|---|
| 不想折腾 Shizuku、想远程用微信/飞书指挥 | **Andclaw**（零依赖，无障碍） |
| 想要最活跃的社区、最完整的工程实现 | **肉包 Roubao**（2.4k★，Kotlin 重写） |
| 想要内置定时任务 + 多通道 + 有商业支持 | **ApkClaw** |
| 只想做淘宝/支付宝签到，不想碰 AI | **Hamibot 淘宝签到助手**（免费现成） |

**我的建议**：先装 **Andclaw**（不需要 Shizuku、不需要恢复出厂，装上就能试）+ 一个 DeepSeek API Key，跑一次淘宝签到。验证通过后再决定要不要换肉包。
