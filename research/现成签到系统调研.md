# 现成签到系统能不能直接用 —— 调研

调研时间：2026-10-29
目的：先判断有没有现成系统能直接用，而不是自己写。

---

## 结论先行

**没有能直接用的完整方案。** 但有两块可以大幅减少工作量：

| 需求 | 有没有现成的 | 结论 |
|---|---|---|
| **淘宝签到（UI 自动化）** | ✅ **Hamibot 有现成脚本** | **值得直接试**，省掉最大的工作量 |
| **调度 + Web 面板 + 多账号 + 通知** | ✅ 有（青龙 / QD / SignMate） | 但它们**只能跑 HTTP 请求，不能操作 App** |
| **签到收益记账（积分→人民币）** | ❌ **没有** | 这是真正的空白，必须自己写 |
| **手机 UI 自动化的通用框架** | ⚠️ 半有 | 设备农场类项目多，但不适配签到场景 |

**核心矛盾**：现成的签到系统全是「HTTP 请求派」（抓包重放），而你要的是「手机 UI 自动化派」。两派的调度层不通用。

---

## 一、HTTP 派（现成系统的主力）

### QD 框架（qd-today/qd，5580 stars）

- 定位：**HTTP 请求定时任务自动执行框架**，基于 HAR 编辑器 + Tornado
- 用法：抓包导出 HAR → 上传 → 自动变成定时任务
- 模板库：`qd-today/templates`（1618 stars）、`wjf0214/qd-templates`（656 stars）
- 有 Web 面板、多任务、通知

**致命限制**：只能发 HTTP 请求。**它完全不能操作 App 界面。**

### binux/qiandao（3426 stars）

同上思路，更老的版本（HAR 模板 + Web 面板），现在由 a76yyyy 维护。

### 青龙面板（whyour/qinglong，20029 stars）

不是签到系统，是通用定时任务面板。能力取决于你导进去什么脚本。同样，脚本基本都是 HTTP 派。

### SignMate（HughRyu/SignMate）

Node.js + Express + **Playwright**，插件式 Driver 架构，Web 管理界面，支持 CookieCloud 同步、代理、WebDAV 备份。
比 QD 现代，但**是浏览器自动化，不是安卓 App 自动化**。

**为什么这些都不够**：淘宝签到（红包签到、淘金币）在 App 里，而且淘宝对 HTTP 接口有风控（`X-Argus` 那类设备签名）。抓包重放要么失效，要么触发风控。

---

## 二、UI 自动化派（能操作 App，但没有平台化）

### ⭐ Hamibot 淘宝签到助手（值得直接试）

**这是本次调研最有价值的发现。**

- 地址：https://hamibot.com/marketplace/5WOon
- 开发者：一只夜猫（认证开发者）
- 更新时间：**2026-10-18**（很新）
- 价格：**免费**
- 权限：显示悬浮窗

**支持的任务（官方描述原文）**：

淘宝：
- 红包签到：赚元宝领现金
- 看视频：赚金豆换现金
- 领淘金币
- 淘金币双11
- 芭芭农场

支付宝：
- 芭芭农场领肥料
- 蚂蚁森林收能量
- 玩赚支付宝：签到领现金
- 支付宝会员：签到赚积分
- 福气鱼塘：钓鱼领红包
- 领赏金红包：支付立减

**特性**：
- 可配置只做某些任务、不做某些任务
- 单个任务最多重试 3 次，3 次失败自动跳过（不会卡死）

**这正好覆盖你要的淘宝签到全部入口**，包括我建议二期做的芭芭农场。

另一个相关脚本：`淘宝签到领现金`（6UP8y，2023-01，付费 ¥0.8/月）—— 明确写着「**脚本支持小米的系统双开**」，这点对多账号很有参考价值，但太老（2023）且付费。

### JavisPeng/taojinbi（1477 stars）

淘金币 + 蚂蚁森林 + 芭芭农场全任务的 AutoJs 脚本。功能最全。

**但已基本停更**：
- 最后一次 release v1.5.5 @ 2026-01-22
- 作者原话：「由于个人问题（年后换工作），以后将不定期维护该项目」
- fork：`htfcuddles/Ant-Credits`（基于 TonyJiangWJ/AutoScriptBase 重构，支持图形化配置）

### TonyJiangWJ/Unify-Sign（724 stars）

聚合签到，覆盖京东/支付宝/淘宝/叮咚/微博/芭芭农场/华住会/小米商城/饿了么/什么值得买/阿里云盘/原神等约 20 个 App。
带可视化配置、随机化执行计划、分组。但**最后推送 2025-05**，一年半没更新。

## 三、记账：真正的空白

搜遍 GitHub 和 Google，**没有任何项目做「签到收益记账」**：

| 搜过的方向 | 结果 |
|---|---|
| `羊毛 收益 记账 面板` | 0 |
| `积分 收益 换算 记账 工具` | 0 |
| `reward tracking checkin` | 无相关 |
| 薅羊毛类项目 | 全是**怎么赚**，没有**赚了多少、值多少钱** |

现有项目最多给个「签到成功/失败」日志（青龙的运行日志、Hamibot 的脚本日志），**没有一个把积分折算成人民币、按账号/活动/时间维度汇总**。

**这就是必须自己写的部分，也正是你要求的「平台化」。**

## 四、关键判断：为什么不能直接用现成系统

### 派系不兼容

```
HTTP 派（QD / qiandao / SignMate / 青龙脚本）
  └─ 能力：发请求、改 cookie、解析响应
  └─ 优点：轻、快、有现成面板
  └─ 致命：不能点 App 里的按钮

UI 自动化派（Hamibot / AutoJs6 / Unify-Sign）
  └─ 能力：点、滑、长按、看界面
  └─ 优点：能操作 App，不怕接口风控
  └─ 缺陷：没有平台化（没多账号管理、没收益统计、没统一面板）
```

**你要的是「UI 自动化的执行能力 + 平台化的记账/面板」。这个组合市面上没有。**

### 已有的组合尝试

| 项目 | 做到什么程度 | 缺什么 |
|---|---|---|
| 青龙 + AutoJs 脚本 | 有调度有日志 | 无收益记账，脚本要自己写 |
| Hamibot | 有脚本有云端定时有 REST API | 无收益记账，无多账号统一视图 |
| Unify-Sign | 有聚合有可视化配置 | 无 Web 面板，无记账，已停更 |

## 五、可选的三种路线

### 路线 A：Hamibot 打主力 + 自建记账层（推荐）

```
签到执行：Hamibot 装「淘宝签到助手」（现成、免费、2026-10 更新）
调度：Hamibot 云端定时（免费额度 1 个定时任务）
多账号：Hamibot 支持多设备配对（免费 1 个，超出 ¥1/次）
记账：自己写（读 Hamibot 的脚本日志 + 我们自己抓 App 里的余额）
面板：自己写（Mac 本地）
```

**优点**：签到逻辑一行不用写，直接能用。
**缺点**：依赖 Hamibot 平台；收益数据要么靠 Hamibot 日志（可能不全），要么我们另外开 App 抓余额（多一步操作）。

### 路线 B：自建全链路（原方案）

```
执行：uiautomator2 + adb（已实测可用）
调度：Mac cron / Hermes cron
记账：自己写
面板：自己写
```

**优点**：完全自主，收益数据直接从 App 界面读，最准。
**缺点**：签到流程要自己写（虽然 L2 能自学习，但初期要投入）。

### 路线 C：混合 —— Hamibot 跑签到，自建层读余额

```
签到：Hamibot（现成）
记账：我们的引擎每天多跑一步「打开 App 读余额」，从界面抓当前积分/金币数
面板：自己写
```

**这个方案最实际**：
- 签到不用写（Hamibot 现成）
- 收益最准（直接读 App 里的真实余额，不是猜「签到得了多少」）
- 顺带解决「签到到底成没成功」的验证问题 —— 余额涨了就是成功

## 六、我的建议

**先花 30 分钟验证路线 C 的前半段：Hamibot 的淘宝签到助手能不能在你的手机+账号上跑通。**

理由：
1. 它免费、2026-10-18 刚更新、覆盖淘宝全部签到入口
2. 如果它能跑通，我们省掉最大的一块工作量
3. 如果跑不通（比如账号版本不兼容、被风控），再走路线 B 也不迟

**验证清单**：
- [ ] 手机装 Hamibot，配对设备
- [ ] 装「淘宝签到助手」脚本
- [ ] 跑一次，看能不能完成红包签到 + 淘金币
- [ ] 看日志能不能读到「得了多少」
- [ ] 跑一次大概多久

**无论哪条路线，记账和面板都得自己写。** 这部分没有现成的。
