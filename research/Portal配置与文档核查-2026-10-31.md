# Portal配置与文档核查

范围：先查官方文档和现成配置；未连接或采样手机，未修改业务代码、权限、服务或调度。

## 结论

有应先检查的配置，但在已安装Portal v0.7.30的官方本地API文档、README和配置定义中，未找到可调整层级读取2秒预算或关闭旧快照回退的公开配置。不能把这个结论扩展为所有未来版本均不可调。

| 项目 | 官方说明 | 与当前问题的关系 |
| --- | --- | --- |
| Unrestricted Battery | Portal Settings → Permissions；README建议本地服务器常驻时启用 | 应先核对，防止后台服务受限；不能保证解决亮屏前台的读树超时。本轮未检查设备设置 |
| Keep Screen Awake | Portal设置或WebSocket screen/keepAwake/set | 防止休眠；前一步已观察Awake，不足以解释当时超时，不应长期强制开启 |
| filter=true/false | state_full、a11y_tree_full的请求参数；过滤树内容 | 现成参数，应优先验证字段完整性与开销；前一步过滤后316节点仍有错误，未证明解决问题 |
| HTTP Server / WebSocket Server / port | 本地服务开关与端口 | 控制传输；不能推断换传输便绕过同一个读树预算 |
| Framework use_tcp | Python框架选择HTTP或ContentProvider | 框架配置，不是Portal读树超时；现有TS项目直接调用Portal，不会自动读取该框架YAML |
| Framework portal_mode | auto / required / disabled | 框架可切Portal或ADB；不适合在动作结果未知时自动换通道重发 |
| Framework auto_setup | 自动安装或修复Portal | 会有设备副作用；不能在诊断中随意启用 |
| taskPromptExecutionTimeout、MobileAgent timeout | 云端/Agent业务工作流超时 | 不是层级读取超时，修改它不会改变A11Y_READ_TIMEOUT_MS |
| AppCardConfig server_timeout=2.0 | 获取App Card的服务器请求超时 | 与Portal层级读取的2秒不是同一个配置 |

官方v0.7.30的ConfigManager.kt有任务超时、端口、亮屏、overlay等持久配置，没有发现a11y读树超时配置；ApiHandler.kt将A11Y_READ_TIMEOUT_MS声明为private const val 2000。此源码检查用于补足文档未说明的边界，不是继续真机试错。

官方PR #141说明超时回退是为防止Accessibility Binder阻塞拖死整个服务，提到Android窗口内容连接丢失这类平台问题。它支持“这是已知故障保护机制”，不能证明本机本次底层触发原因就是该问题。

## 后续顺序

先按文档核对现有设备配置：不受限电池、无障碍、所需本地服务与休眠策略；只核对当前值，不直接全开。随后有针对性验证filter和通信模式。确认现成配置无解后，才决定是否需要适配逻辑或进一步诊断，不立即改门禁。
