## 6. 多开账号（结论已修正）

### 6.1 早先的错误结论

一开始测到 `adb shell am switch-user 999` 报 `Error: Failed to switch to user 999`，
就下了「HyperOS 禁止 adb 切用户，adb 碰不到分身」的结论。**这是错的。**

### 6.2 修正后的事实（实测）

```
adb shell am start --user 999 -n com.sankuai.meituan/...
→ 前台: mCurrentFocus=Window{fbebc49 u999 com.sankuai.meituan/...}
→ am get-current-user 仍为 0        ← 当前用户没变，但 999 的 App 起来了
```

**关键点**：
- `am switch-user` 确实被禁（不能切「当前用户」）
- 但 `am start --user 999` **可以**直接把 999 里的 App 拉到前台，不需要切换用户
- **uiautomator2 能正常操作它**：`dump_hierarchy` 拿到 80 节点、`click(540,1200)` 成功

实测序列（`/tmp/dualfinal.py`）：

| 步骤 | 前台 | dump 节点 | 点击 |
|---|---|---|---|
| 主用户启动淘宝 | `u0 com.taobao.taobao` | 275 | ✅ |
| 启动双开美团（`--user 999`） | `u999 com.sankuai.meituan` | 80 | ✅ |
| 再回主用户淘宝 | `u0 com.taobao.taobao` | 277 | ✅ |

**结论：同一套 adb / u2 连接，可以交替操控主空间和双开空间的应用。**

### 6.3 双开机制的真实形态

```
adb shell pm list users
UserInfo{0:机主:4c13}      running
UserInfo{999:XSpace:801010} running

pm list packages --user 999 | wc -l  → 22（基础包 + 已双开的 App）
pm list packages --user 999 -3
  package:com.sankuai.meituan      ← 美团已双开
  package:com.netease.l10
```

- 小米「应用双开」= 把 App 装进 **user 999** 这个 profile
- 每个 user 有独立的 `/data/user/<uid>/<pkg>` 数据目录（双开账号独立登录）
- 包名**不变**（还是 `com.sankuai.meituan`），靠 **userId 区分**实例

**所以账号表必须用 `(package, user_id)` 二元组做主键的一部分，不能只用包名。**

### 6.4 我能否自己点开双开（实测）

✅ **能。** 完整路径实测走通：

```
设置 → 下滑找到「应用设置」→ 进入 → 找「应用双开」→ 进入「双开设置」
```

- 「应用设置」在设置首页首屏看不到，需 `swipe` 下滑一次才出现
- 「双开设置」页显示「搜索22个应用」和可双开列表（微信、QQ、美团、倩女幽魂、嗅觉浏览器…）
- 列表行的**文字节点 `clickable=false`**，要点它的可点祖先容器（bounds `[33,1160][1047,1336]` 中心 `(540,1248)`）
- 点已双开的行 → 弹「删除双开应用」确认框，说明开关可正常操作

**踩到的坑**：设置里的搜索框 `EditText` 用 `d(className="android.widget.EditText")` 找不到（count=0），
`d(focused=True).set_text()` 也报 `UiObjectNotFoundError`。所以**走搜索路径不可行，必须走列表导航**。

### 6.5 对方案的影响

账号表增加 `user_id` 字段：

```yaml
- id: mt_dual
  app: meituan
  package: com.sankuai.meituan
  user_id: 999          # 双开实例
  space: dual
```

引擎启动 App 时用 `am start --user <user_id>`，而不是 `app_start`（u2 的 `app_start` 默认只起当前用户）。

**6 个里 4 个掉线。** 这是每日签到的第一瓶颈，比活动改版更常见。

### 小红书的两种故障要区分

- **未登录**：停在登录页
- **被挤下线**：信息流还在，但有「账号下线通知」模态框盖住整屏，只留「重新登录」

后者如果不识别，后续所有点击都落在弹窗上 —— **脚本会「看起来执行成功」却什么都没签到**。这类误报比失败更危险。

## 8. uiautomator2 的四个坑（实测）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | `d(text="红包签到").exists` 返回 false，但 XML 里明确有该文本 | selector 内部匹配失败 | fallback 到解析 XML + 按 bounds 中心 `d.click(x,y)` |
| 2 | 熄屏时 `dump_hierarchy` 只返回 20 个 systemui 节点 | 屏幕关闭 | dump 前检查 `screenOn`，否则先 `KEYCODE_WAKEUP` |
| 3 | `app_current()` 前台是淘宝却返回美团 `YodaRouterTransparentActivity` | 残留任务 | 读 `dumpsys window mCurrentFocus` + 校验包名前缀 |
| 4 | `app_start` 静默失败，前台仍是旧 App | 别的 App 模态框挡住 | `app_stop` 后重试，最多 3 次 |

这四条都已写进 `runner/checkin.py`。
