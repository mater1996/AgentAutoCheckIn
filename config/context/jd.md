# 京东 · 京豆签到经验

> 这份文件会被注入 Midscene 的 AI 上下文（`setAIContext('default', ...)`）。

## 你在做什么

你在替用户在京东 App 里完成「京豆」签到。
**100 京豆 = ¥1**，180 天过期，下单时单笔最多抵订单金额的 50%。

## 入口路径（实测 2026-10-30）

1. 底部导航栏点「我的」，进入个人中心
2. 点「京豆」入口，进入京豆页面
3. **签到入口实测叫「立即刮卡」，不是「签到」**——找「签到」按钮会找不到

## 关键坑（踩过）

### 1. 跨页读数会产生负数

- 「我的」页面显示京豆**总数**（实测 888）
- 京豆页面显示「**今日获得** 3」

这两个数**不能相减**。之前就是这样读出了 `888 → 3`，被判定为读数错误，整轮作废。

**规则：必须在同一个页面读同一个指标。**

### 2. 刮卡是任务门控

京豆页面可能显示「**做任务解锁刮卡**」而不是「立即刮卡」。
这时说明今天要先完成任务才能刮卡，不是签到失败。

### 3. 京东首页底部导航是 content-desc

底部导航以 `content-desc` 暴露：首页 / 我的 / 购物车 / 消息 / 分类。
不要用「搜索栏」「推荐」判断是否在首页——这两个词在京豆等二级页面也会出现。

## 绝对不要做

- **遇到「验证后，购物更轻松~」这类验证页：立即停止**，不要尝试绕过
- 不要点「开通 PLUS」「领券中心」「白条」等诱导入口
- 不要点任何需要支付、绑卡、授权的按钮
- 不要点「立即提现」「金币兑换现金」这类入口

## 读数规则

- 京豆**总数只在京豆页面读**
- 如果读到 3、5 这种很小的数字，大概率是「今日获得」而不是总数，**判为读错**
- 同一次运行里，`before` 和 `after` 必须读同一位置

## 常见失败与对策

| 现象 | 处理 |
|---|---|
| 找不到「签到」按钮 | 入口叫「立即刮卡」 |
| 显示「做任务解锁刮卡」 | 是任务门控，不是失败；记录并退出 |
| 出现验证页 | 立即停止，标记需要人工 |
| 读数异常小 | 读到了「今日获得」，换位置重读 |

## 收益经验值

- 每日签到约 **7~10 京豆**（¥0.07~0.10）
- 金额很小，**优先级低于淘宝淘金币**
- 主要价值是保持签到连续性，不是金额
